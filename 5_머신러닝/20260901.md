## 1. 허깅페이스 생태계와 핵심 컴포넌트

허깅페이스(Hugging Face)는 전 세계 연구자와 엔지니어들이 사전 학습된(Pre-trained) 딥러닝 모델과 대규모 데이터셋을 공유하고 활용할 수 있도록 지원하는 AI 오픈소스 플랫폼이다.

- 바닥부터 신경망 구조를 직접 설계하고 대규모 학습을 진행하지 않아도, 검증된 가중치를 불러와 곧바로 추론 및 미세조정(Fine-tuning)에 적용할 수 있다.
- 자연어 처리를 위한 `transformers` 라이브러리를 통해 통일된 인터페이스를 제공한다.

### 1.1 Pipeline

`pipeline`은 전처리(토큰화), 모델 추론, 후처리(디코딩 및 라벨 매핑) 과정을 하나의 고수준 함수로 추상화한 API이다.

~~~python
from transformers import pipeline

generator = pipeline(
    "text-generation",
    model="google/gemma-2b-it"
)
~~~

- `"text-generation"`과 같이 수행하려는 태스크 이름을 지정한다.
- 모델 식별자(`model="google/gemma-2b-it"`)를 전달하면 적합한 토크나이저와 모델 아키텍처를 자동으로 내려받아 파이프라인 객체를 생성한다.

### 1.2 AutoClasses

`AutoClass`는 모델의 저장소 이름이나 경로만 입력받아 해당 모델의 설정 파일(`config.json`)을 분석하고 적절한 클래스를 동적으로 생성하는 도구이다.

~~~python
from transformers import AutoTokenizer, AutoModelForSequenceClassification

tokenizer = AutoTokenizer.from_pretrained("monologg/kobert")
model = AutoModelForSequenceClassification.from_pretrained(
    "rkdaldus/ko-sent5-classification"
)
~~~

- `AutoTokenizer.from_pretrained()`는 모델 학습에 사용된 어휘 사전과 동일한 서브워드 분절 규칙을 자동으로 로드한다.
- `AutoModelForSequenceClassification.from_pretrained()`는 백본 트랜스포머 모델 위에 분류 헤드(Classification Head)가 부착된 모델을 불러온다.

## 2. 토크나이저와 서브워드 토큰화

딥러닝 모델은 문자열 형태의 텍스트를 직접 연산할 수 없으므로, 문장을 최소 의미 단위인 토큰(Token)으로 분할하고 각 토큰에 고유한 정수 인덱스(Token ID)를 매핑하는 토크나이저(Tokenizer)가 필수적이다.

~~~text
[토큰화 처리 흐름]
원문 텍스트 입력 ("오늘 날씨가 좋다.")
      │
      ▼
서브워드 토큰화 수행 (['오늘', '날씨', '##가', '좋다', '.'])
      │
      ▼
정수 인덱스(Token ID) 매핑 ([1203, 3421, 582, 4891, 18])
      │
      ▼
모델의 임베딩 레이어로 입력 전달
~~~

### 2.1 BPE (Byte Pair Encoding)

BPE는 데이터셋 내에서 가장 자주 연속해서 등장하는 글자(또는 바이트) 쌍을 반복적으로 병합하여 어휘 사전을 구축하는 통계적 서브워드 분절 방식이다.

- 자주 쓰이는 복합 단어는 하나의 통토큰으로 유지하고, 희귀 단어는 의미 있는 작은 단위로 쪼개어 미등록 단어(OOV, Out of Vocabulary) 문제를 방지한다.
- GPT 계열 및 다수의 현대 거대 언어 모델(LLM)에서 채택하고 있다.

### 2.2 WordPiece

WordPiece는 BPE와 유사하게 빈도수를 활용하지만, 단순히 등장 빈도만 비교하는 대신 병합 시 언어 모델의 우도(Likelihood) 증가량을 통계적 기준으로 삼아 단어를 분절한다.

- 토큰이 단어의 중간에 붙는 접미사일 경우 접두어 기호(예: `##`)를 붙여 위치 정보를 유지한다.
- BERT 계열 모델에서 표준적으로 사용된다.

### 2.3 SentencePiece

SentencePiece는 언어별 사전 형태소 분석이나 띄어쓰기 규칙에 의존하지 않고, 공백 문자 자체를 특수 기호(예: `_`)로 치환하여 원문 문자열 전체를 통째로 다루는 비지도 학습 기반 토큰화 라이브러리이다.

- 한국어처럼 조사와 어미가 결합하는 교착어 및 띄어쓰기 규범이 유동적인 언어에서도 OOV 없이 안정적으로 토큰을 추출한다.
- 다국어 사전 모델(mBERT, Llama 등)에서 폭넓게 활용된다.

## 3. 트랜스포머 3대 아키텍처 유형

트랜스포머는 문제를 해결하는 방식에 따라 어텐션 레이어를 배치하는 구조를 세 가지 형태로 나눈다.

- **인코더 전용 (Encoder-Only):**
  - 양방향(Bidirectional) 셀프 어텐션을 사용하여 텍스트의 앞뒤 문맥을 동시에 파악한다.
  - 문장 전체의 의미를 추출하는 작업에 최적화되어 있다.
  - 대표 모델: BERT, RoBERTa, KoBERT
  - 주요 작업: 감정 분석, 문장 분류, 개체명 인식(NER)
- **인코더-디코더 (Encoder-Decoder):**
  - 인코더가 원본 시퀀스의 의미를 벡터 공간에 압축하고, 디코더가 이를 교차 참조(Cross-Attention)하며 새로운 시퀀스를 생성한다.
  - 대표 모델: T5, BART, KoBART
  - 주요 작업: 텍스트 요약, 기계 번역, 문장 생성형 질의응답
- **디코더 전용 (Decoder-Only):**
  - 이전 토큰들만 참조할 수 있도록 마스크드 셀프 어텐션(Masked Self-Attention)을 적용하여 순차적으로 다음 토큰을 확률적으로 예측한다.
  - 대표 모델: GPT 계열, Gemma, Llama
  - 주요 작업: 자유 대화형 챗봇, 자연어 문장 생성, 코드 작성

## 4. KoBERT를 활용한 감정 분류 실습

인코더 전용 구조를 갖춘 한국어 특화 BERT 모델(KoBERT)을 활용하여 입력 문장의 감정을 5개 범주로 분류하는 파이프라인이다.

### 4.1 모델 및 토크나이저 로드

~~~python
from transformers import AutoTokenizer, AutoModelForSequenceClassification

model_name = "rkdaldus/ko-sent5-classification"

tokenizer = AutoTokenizer.from_pretrained(
    "monologg/kobert",
    trust_remote_code=True
)
model = AutoModelForSequenceClassification.from_pretrained(model_name)
~~~

- `trust_remote_code=True`는 허깅페이스 허브에 등록된 커스텀 토크나이저 코드를 허용하여 로드한다.
- 5가지 감정 분류용 헤드가 결합된 모델을 메모리에 올린다.

### 4.2 텍스트 텐서화 및 추론

~~~python
import torch

text_to_analyze = "오늘 동아리 첫 모임에 나갔는데 선배들도 잘 챙겨주고 다들 착해서 너무 신났어!"

encoded_inputs = tokenizer(
    text_to_analyze,
    return_tensors="pt",
    padding=True,
    truncation=True
)

with torch.no_grad():
    model_outputs = model(**encoded_inputs)
    logits = model_outputs.logits

calculated_probabilities = torch.nn.functional.softmax(logits, dim=-1)
emotion_labels = ["분노", "불안", "기쁨", "평온", "슬픔"]
~~~

- `return_tensors="pt"`는 토큰화된 결과물을 PyTorch의 Tensor 자료형으로 반환하도록 지정한다.
- `padding=True`와 `truncation=True`는 배치 연산을 위해 문장 길이를 일정하게 맞추거나 최대 길이를 초과하는 토큰을 자른다.
- `torch.no_grad()`로 추론 시 불필요한 기울기 계산을 비활성화하여 메모리를 절약한다.
- 모델의 출력값인 `logits`에 `softmax` 함수를 적용하여 각 감정 클래스별 합이 1이 되는 확률값으로 변환한다.

## 5. KoBART를 활용한 뉴스 텍스트 요약 실습

인코더-디코더 구조를 기반으로 긴 한국어 본문 시퀀스를 입력받아 핵심 요약 시퀀스를 생성한다.

### 5.1 토크나이저 및 생성 모델 로드

~~~python
from transformers import PreTrainedTokenizerFast, BartForConditionalGeneration

kobart_identifier = "gogamza/kobart-summarization"

bart_tokenizer = PreTrainedTokenizerFast.from_pretrained(kobart_identifier)
bart_model = BartForConditionalGeneration.from_pretrained(kobart_identifier).to(device)
~~~

- `BartForConditionalGeneration`은 인코더와 디코더를 모두 포함하여 조건부 시퀀스 생성을 수행하는 아키텍처이다.
- `.to(device)`를 호출하여 모델을 GPU 또는 CPU 연산 장치에 할당한다.

### 5.2 요약 시퀀스 생성 및 디코딩

~~~python
input_ids = bart_tokenizer.encode(
    campus_news,
    return_tensors="pt",
    max_length=1024,
    truncation=True
).to(device)

summary_tokens = bart_model.generate(
    input_ids,
    max_length=80,
    min_length=15,
    num_beams=4,
    no_repeat_ngram_size=3,
    early_stopping=True
)

summarized_result = bart_tokenizer.decode(
    summary_tokens[0],
    skip_special_tokens=True
)
print(summarized_result)
~~~

- `encode()`는 원문 텍스트를 인코더의 입력 토큰 ID 텐서로 변환한다.
- `generate()`는 디코더의 자동 회귀(Auto-regressive) 생성을 제어하는 함수이다.
  - `num_beams=4`: 빔 서치(Beam Search)를 통해 매 시점 상위 4개의 유력한 후보 경로를 유지하며 탐색한다.
  - `no_repeat_ngram_size=3`: 연속된 3개 토큰이 중복으로 등장하는 문장 반복 생성을 억제한다.
  - `early_stopping=True`: 모든 빔이 문장 종료 토큰(`<eos>`)에 도달하면 즉시 생성을 종료한다.
- `decode()`는 생성된 토큰 ID 시퀀스를 다시 사람이 읽을 수 있는 자연어 문자열로 변환하며, `skip_special_tokens=True`로 패딩이나 종료 토큰 등의 특수 기호를 제거한다.

## 6. Gemma를 활용한 대화형 텍스트 생성 실습

구글의 디코더 전용 경량 거대 언어 모델인 Gemma를 파이프라인 형태로 구동하여 대화형 프롬프트를 처리한다.

~~~python
import torch
from transformers import pipeline

gemma_generator = pipeline(
    "text-generation",
    model="google/gemma-2b-it",
    dtype=torch.bfloat16,
    device_map="auto"
)

user_dialogue = [
    {
        "role": "user",
        "content": "머신러닝과 딥러닝의 핵심 차이점을 비전공자 대학생에게 딱 한 문장으로 비유해서 알려줘."
    }
]

generation_outputs = gemma_generator(
    user_dialogue,
    max_new_tokens=150
)
~~~

- `dtype=torch.bfloat16`을 적용하여 16비트 부동소수점 정밀도로 연산함으로써 메모리 사용량을 줄이고 추론 속도를 높인다.
- `device_map="auto"`는 시스템 내 가용 하드웨어(GPU, CPU)를 감지하여 모델 가중치를 효율적인 위치에 자동 분산 배치한다.
- `role`과 `content`를 가진 딕셔너리 리스트 구조(Chat Template)로 대화 맥락을 구성하여 모델에 전달한다.
- `max_new_tokens=150`을 통해 입력 프롬프트 길이와 상관없이 새롭게 생성할 토큰의 최대 상한선을 지정한다.

## 7. 트랜스포머 모델의 파라미터 구조

트랜스포머 내부의 파라미터는 크게 네 가지 핵심 레이어에서 발생하며, 은닉 차원($d_{\text{model}}$)과 어휘 사전 크기($\text{Vocab Size}$)에 의해 전체 규모가 결정된다.

### 7.1 토큰 임베딩 (Token Embedding)

- 정수 토큰 인덱스를 연속적인 실수 벡터로 사상하는 룩업 테이블(Lookup Table)이다.
- 파라미터 수 계산:
  $$\text{Vocab Size} \times d_{\text{model}}$$

### 7.2 멀티 헤드 어텐션 (Multi-Head Attention)

- 입력 벡터를 Query($Q$), Key($K$), Value($V$) 공간으로 선형 변환하는 세 개의 투사 행렬과, 결합된 결과를 다시 합치는 출력 투사 행렬($O$)로 구성된다.
- 파라미터 수 계산:
  $$(d_{\text{model}} \times d_{\text{model}} \times 3) + d_{\text{model}}^2$$

### 7.3 피드 포워드 네트워크 (Feed-Forward Network, FFN)

- 어텐션을 통과한 벡터를 더 큰 중간 차원($d_{\text{ff}}$)으로 확장했다가 다시 축소하는 2단계 완전연결 신경망이다.
- 일반적으로 $d_{\text{ff}}$는 $d_{\text{model}}$의 4배 수준으로 설정되어 모델 내에서 가장 큰 파라미터 비중을 차지한다.
- 파라미터 수 계산:
  $$(d_{\text{model}} \times d_{\text{ff}}) + (d_{\text{ff}} \times d_{\text{model}})$$

### 7.4 최종 투사층 (Output Projection Layer)

- 디코더의 마지막 은닉 상태를 전체 어휘 사전 크기만큼의 점수(Logits)로 펼쳐 다음 단어를 예측할 수 있도록 변환한다.
- 파라미터 수 계산:
  $$d_{\text{model}} \times \text{Vocab Size}$$

## 8. 비교 정리

### 8.1 서브워드 토큰화 기법 비교

| 구분 | BPE (Byte Pair Encoding) | WordPiece | SentencePiece |
|---|---|---|---|
| **병합 기준** | 단순 빈도수가 높은 바이트 쌍 | 언어 모델의 우도(Likelihood) 기준 | 공백 포함 문자열 기반 통계 모델 |
| **공백 처리** | 공백을 기준으로 1차 분절 후 병합 | 단어 내부 서브워드에 접두어(`##`) 부여 | 공백 자체를 대체 문자(`_`)로 보존 |
| **대표 모델** | GPT 계열 | BERT 계열 | mBERT, T5, Llama |

### 8.2 트랜스포머 3대 아키텍처 비교

| 구분 | 인코더 전용 (Encoder-Only) | 인코더-디코더 (Encoder-Decoder) | 디코더 전용 (Decoder-Only) |
|---|---|---|---|
| **어텐션 방식** | 양방향 셀프 어텐션 | 양방향 셀프 + 인과적 + 크로스 어텐션 | 인과적(마스크드) 셀프 어텐션 |
| **작동 원리** | 전체 문맥을 한 번에 양방향 분석 | 입력을 인코딩 후 디코더가 출력 생성 | 이전 토큰들을 참조하며 다음 토큰 예측 |
| **대표 모델** | KoBERT | KoBART | Gemma |
| **핵심 작업** | 텍스트 분류, 감정 분석, NER | 문서 요약, 기계 번역 | 대화형 생성, 자유 텍스트 생성 |

## 9. 전체 흐름 정리

허깅페이스 라이브러리를 활용하여 자연어 처리 모델을 구동하는 전체 파이프라인 흐름은 다음과 같다.

~~~text
[1. 작업 정의 및 모델 선정]
분류/요약/생성 목적에 따라 인코더, 인코더-디코더, 디코더 모델 선택
      │
      ▼
[2. 토크나이저 및 모델 로드]
AutoTokenizer와 AutoModel 클래스를 통해 가중치 및 어휘 사전 로드
      │
      ▼
[3. 입력 데이터 전처리]
원문 문자열을 서브워드로 분절하고 Token ID 및 Attention Mask 텐서 생성
      │
      ▼
[4. 모델 추론 (Forward Pass)]
- torch.no_grad() 환경에서 인코더/디코더 레이어 통과
- 멀티 헤드 어텐션 및 FFN 연산을 거쳐 Logits 계산
      │
      ▼
[5. 후처리 및 결과 도출]
- 분류 모델: Softmax 적용 후 클래스 확률 계산
- 생성/요약 모델: generate() 빔 서치 수행 후 토큰을 문장으로 디코딩
~~~

## 10. 핵심 정리

### 핵심 코드

~~~python
from transformers import AutoTokenizer, AutoModelForSequenceClassification
import torch

# 1. 토크나이저 및 모델 로드
tokenizer = AutoTokenizer.from_pretrained("monologg/kobert")
model = AutoModelForSequenceClassification.from_pretrained("rkdaldus/ko-sent5-classification")

# 2. 토큰화 및 PyTorch 텐서 변환
inputs = tokenizer("문장 입력", return_tensors="pt", padding=True, truncation=True)

# 3. 추론 및 확률 변환
with torch.no_grad():
    outputs = model(**inputs)
    probs = torch.nn.functional.softmax(outputs.logits, dim=-1)
~~~

- `AutoTokenizer`를 통해 원문을 모델의 서브워드 토큰 인덱스로 인코딩한다.
- `AutoModel`을 통해 신경망을 통과시켜 원시 점수인 `logits`를 산출한다.
- `softmax` 함수를 통해 각 라벨에 대한 최종 예측 확률을 도출한다.

### 핵심 개념

- 허깅페이스는 `pipeline`과 `AutoClass`를 통해 모델 로드와 전처리, 추론을 단 몇 줄의 코드로 표준화한다.
- 서브워드 토큰화(BPE, WordPiece, SentencePiece)는 빈도 및 통계 기준에 따라 단어를 세부 단위로 쪼개어 미등록 단어 문제를 방지한다.
- 트랜스포머는 문맥을 이해하고 분류하는 인코더 전용, 시퀀스 변환과 요약에 특화된 인코더-디코더, 자귀회귀적 텍스트 생성을 담당하는 디코더 전용으로 구분된다.

## 11. 느낀 점

트랜스포머 아키텍처를 단순히 이론적인 블록 다이어그램으로만 접했을 때는 각 구성 요소가 어떻게 동작하는지 체감하기 어려웠으나, 허깅페이스 라이브러리를 통해 실제 모델을 다뤄보며 각 아키텍처의 차이점을 명확히 이해할 수 있었다. 문맥 전체를 양방향으로 파악하는 KoBERT는 문장의 감정을 분류하는 데 적합하고, 인코더와 디코더가 결합된 KoBART는 긴 뉴스 기사의 문맥을 압축하여 요약문을 만드는 데 탁월하며, 단방향 어텐션을 적용하는 Gemma는 다음 단어를 자연스럽게 이어 붙이는 생성 작업에 강점이 있다는 것을 실습을 통해 체득했다. 또한 모델의 연산 과정 이전에 BPE나 SentencePiece 같은 토크나이저가 원문을 서브워드로 적절히 분절하고 정수 텐서로 변환해 주는 전처리 단계가 모델 성능과 직결된다는 점을 배웠다. 앞으로 실무에서 NLP 문제를 해결할 때는 당면한 과제가 이해, 변환, 생성 중 어디에 해당하는지 먼저 정의하고, 이에 최적화된 아키텍처와 토크나이저를 선별하여 파이프라인을 구축해야겠다고 느꼈다.

## 1. 생성형 AI의 기본 구조

AI는 가장 포괄적인 개념이며, 머신러닝과 딥러닝을 거쳐 생성형 AI와 LLM으로 구체화된다.

- **인공지능(AI):** 인간의 지능적 행동을 컴퓨터로 모방하는 기술 전체를 의미한다.
- **머신러닝(ML):** 데이터를 학습하여 기계가 스스로 패턴과 규칙을 찾아내는 방식이다.
- **딥러닝(DL):** 인공 신경망(Neural Network)을 여러 층으로 쌓아 복잡하고 방대한 데이터를 학습하는 기술이다.
- **생성형 AI:** 학습한 데이터의 패턴을 기반으로 새로운 텍스트, 이미지, 코드 등을 생성하는 인공지능이다.
- **LLM(대규모 언어 모델):** 방대한 텍스트 데이터를 사전에 학습하여 자연스러운 언어를 이해하고 생성하는 대형 언어 모델이다.

## 2. 토큰과 임베딩

AI는 사람이 작성한 텍스트를 있는 그대로 처리하지 못하므로, 데이터를 쪼개고 수치화하는 단계를 거친다.

### 2.1 토큰 (Token)

토큰은 AI 모델이 텍스트를 처리할 때 사용하는 기본 단위이다.

- 단어와 토큰이 항상 1:1로 일치하지는 않는다.
- 영어는 보통 한 단어가 하나의 토큰에 가깝지만, 한국어는 조사나 어미 결합에 따라 하나의 단어가 여러 토큰으로 분리될 수 있다.
- 프로그래밍 코드의 기호나 괄호, 공백 역시 독립된 토큰으로 분할된다.
- 토큰 수는 API 사용 비용과 한 번에 처리할 수 있는 입력량(컨텍스트 윈도우)을 결정하는 핵심 단위이다.

> 예시: "나는 AI를 사랑한다." → `나` + `는` + ` AI` + `를` + ` 사랑` + `한다` + `.` 형태로 분할된다.

### 2.2 임베딩 (Embedding)

임베딩은 분할된 토큰을 컴퓨터가 수학적으로 연산할 수 있도록 다차원 숫자 벡터로 변환하는 과정이다.

- 텍스트 입력 → 토큰화 → 임베딩 벡터 변환 순서로 진행된다.
- 의미나 사용 맥락이 유사한 단어일수록 벡터 공간상에서 가까운 거리에 위치한다.
- 단어 사이의 관계와 개념적 유사도를 수치화하여 AI가 맥락을 계산할 수 있게 돕는다.

## 3. 다음 토큰 예측과 Temperature

생성형 AI는 데이터베이스에서 완성된 답변을 찾아오는 것이 아니라 확률을 계산하여 글을 이어 나간다.

### 3.1 다음 토큰 예측 (Next-Token Prediction)

LLM의 기본 동작 메커니즘은 문맥에 맞추어 가장 적절한 다음 토큰을 확률적으로 선택하는 것이다. 이러한 답변 생성 과정을 추론(Inference)이라 한다.

~~~text
프롬프트 입력
    │
    ▼
문맥 분석 및 다음 토큰 확률 계산
    │
    ▼
토큰 하나 생성 후 기존 문맥에 결합
    │
    ▼
확장된 문맥을 바탕으로 다시 다음 토큰 예측
    │
    ▼
반복 수행 후 최종 답변 완료
~~~

### 3.2 Temperature

Temperature는 다음 토큰을 선택할 때 확률 분포의 무작위성(다양성)을 제어하는 하이퍼파라미터이다.

| 설정 값 | 특징 | 적합한 작업 |
|---|---|---|
| 낮음 (0에 가까움) | 가장 확률이 높은 토큰을 엄격하게 선택하여 일관되고 예측 가능한 답변 생성 | 코드 작성, 번역, 사실 요약 |
| 중간 | 안정성과 창의성 사이의 균형 유지 | 일반 글쓰기, 비즈니스 문서 작성 |
| 높음 (1에 가까움) | 다양한 후보 토큰을 선택하여 창의적이고 변칙적인 답변 생성 | 브레인스토밍, 광고 카피, 소설 창작 |

## 4. 환각과 컨텍스트 윈도우

생성형 AI를 활용할 때 주의해야 할 물리적, 논리적 제약 사항이다.

- **환각(Hallucination):** 모델이 사실 여부를 검증하고 답변하는 것이 아니라 확률적으로 그럴듯한 문장을 구성하기 때문에, 잘못되거나 존재하지 않는 정보를 사실처럼 만들어내는 현상이다.
- **컨텍스트 윈도우(Context Window):** AI가 한 번의 추론 과정에서 참고할 수 있는 최대 토큰 한도이다. 대화가 길어져 이 범위를 초과하면 앞부분의 지시사항이나 데이터가 누락될 수 있다.

## 5. 컨텍스트 엔지니어링

컨텍스트 엔지니어링은 AI가 원하는 결과물을 도출할 수 있도록 역할, 배경, 제약 사항, 출력 형식 등의 맥락을 구조화하여 제공하는 기법이다.

- 단순 프롬프팅: 질문 위주로 짧게 요청하는 방식이다.
- 컨텍스트 엔지니어링: AI에게 명확한 역할과 제약 조건을 부여하는 구조화된 방식이다.

~~~text
[컨텍스트 엔지니어링 적용 예시]
- 역할: 너는 IT 기기 마케터이다.
- 제품: 20대 대학생을 타깃으로 하는 가성비 무선 이어폰이다.
- 작업: 인스타그램 릴스에 활용할 홍보 문구를 작성한다.
- 어조: 유머러스하고 트렌디한 어조를 유지한다.
- 출력 형식: 추천 문구 3개를 표(Table) 형태로 정리한다.
~~~

## 6. 주요 생성형 AI 모델

작업 목적과 데이터 형태에 맞춰 적합한 모델을 선택하여 사용해야 한다.

- **GPT:** 텍스트 작성, 코딩, 데이터 분석 등 폭넓은 범용성을 갖춘 모델이다.
- **Claude:** 긴 문서 처리와 문맥 유지에 강점이 있어 보고서, 계약서 검토, 복잡한 문서 분석에 적합하다.
- **Gemini:** 텍스트와 대규모 멀티모달 입력(영상, 대형 PDF 등)을 효율적으로 처리하며, 다양한 생태계 도구와 연계된다.
- **Llama:** 오픈 소스 계열 모델로, 기업 내부 인프라(온프레미스)에 직접 배포하거나 특정 도메인에 맞춰 미세 조정(Fine-tuning)하기 용이하다.

## 7. 멀티모달 AI

텍스트뿐만 아니라 이미지, 영상, 오디오 등 서로 다른 형태(Modal)의 정보를 함께 처리하는 기술이다.

- **개념:** 단일 형태의 데이터만 처리하던 한계를 넘어, 이미지와 텍스트 또는 음성과 영상을 교차 분석한다.
- **문서 AI(Document AI):** 단순 글자 인식(OCR)을 넘어 문서 레이아웃, 차트, 표, 그래프를 종합적으로 이해하고 구조화한다.
- **주요 활용:** 금융 보고서 종합 분석, 보안 관제(영상/패턴 분석), 멀티미디어 콘텐츠 제작 등에 폭넓게 쓰인다.

## 8. 바이브 코딩과 AI 툴 스택

### 8.1 바이브 코딩 (Vibe Coding)

개발자가 문법 규칙과 세부 코드를 일일이 직접 작성하지 않고, 자연어로 요구사항을 설명하여 AI가 코드를 생성하도록 유도하는 개발 접근법이다.

- 기능 요건을 자연어로 지시하고 생성된 결과를 점검하며 코드를 완성한다.
- AI가 생성한 코드는 보안 취약점이나 논리적 오류를 포함할 수 있으므로, 최종 동작 검증과 리뷰가 필수적이다.

### 8.2 AI 툴 스택 (Tool Stack)

하나의 범용 도구에만 의존하지 않고 작업 단계별 최적의 도구를 연계하여 사용하는 환경 구성이다.

~~~text
정보 검색 및 조사 (Search AI)
    │
    ▼
구조화 및 목차 기획 (LLM)
    │
    ▼
초안 작성 및 코드 개발 (Claude / GPT / Cursor)
    │
    ▼
시각화 및 미디어 생성 (Image / Multimodal AI)
    │
    ▼
결과물 검증 및 수정 (인간 검토)
~~~

## 9. AI 리터러시

AI 도구를 맹신하지 않고 유효성을 평가하며 목적에 맞게 안전하게 제어하는 역량이다.

- **기본 원리 이해:** AI, 머신러닝, LLM의 작동 한계를 인지한다.
- **비판적 검증:** 환각과 지식 컷오프(학습 데이터 기준 시점)를 확인하고 공식 문서로 교차 검증한다.
- **윤리 및 규제 준수:** 입력 프롬프트 내 개인정보 유출 방지 및 저작권 침해 위험성을 관리한다.
- **도구 선택 역량:** 해결하려는 문제의 성격에 적합한 모델과 프롬프트를 구성한다.

## 10. 비교 정리

### 10.1 핵심 개념 비교

| 구분 | 개념 정의 | 핵심 역할 및 특징 |
|---|---|---|
| **AI** | 인간의 지능을 모방하는 기술 | 가장 넓은 범주의 인공지능 기술 |
| **머신러닝** | 데이터 기반 학습 기술 | 데이터로부터 스스로 패턴과 규칙을 학습 |
| **딥러닝** | 인공 신경망 기반 머신러닝 | 다층 신경망으로 복잡한 고차원 데이터 처리 |
| **생성형 AI** | 콘텐츠 창작 중심 인공지능 | 학습 데이터를 조합하여 새로운 산출물 생성 |
| **LLM** | 대규모 언어 모델 | 자연어 토큰 확률 예측 기반의 텍스트 처리 |
| **멀티모달 AI**| 다종 데이터 통합 처리 AI | 텍스트, 이미지, 음성, 영상 동시 분석 |

### 10.2 프롬프팅 방식 비교

| 구분 | 일반적인 프롬프팅 | 컨텍스트 엔지니어링 |
|---|---|---|
| 접근 방식 | 질문 및 요청 위주 | 맥락, 배경, 조건의 구조화 |
| 제공 정보 | 단순 지시어 | 역할, 목표, 제약, 데이터, 출력 서식 |
| 답변 결과 | 범용적이고 일반적인 답변 | 목표와 형식에 부합하는 정밀한 답변 |

## 11. 전체 흐름 정리

생성형 AI가 사용자의 입력을 받아 최종 산출물을 도출하는 전체 파이프라인은 다음과 같다.

~~~text
[1. 입력]
사용자가 프롬프트(지시사항, 맥락) 입력
    │
    ▼
[2. 토큰화]
텍스트를 모델의 처리 단위인 토큰으로 분할
    │
    ▼
[3. 임베딩]
토큰을 수치 형태의 다차원 벡터로 변환
    │
    ▼
[4. 추론]
컨텍스트 윈도우 내에서 문맥을 분석하고 다음 토큰 확률 계산
(Temperature 설정을 반영하여 무작위성 제어)
    │
    ▼
[5. 생성 및 반복]
선택된 토큰을 문맥에 덧붙이며 다음 토큰을 순차적으로 생성
    │
    ▼
[6. 검증 (AI 리터러시)]
완성된 산출물의 환각 여부 및 품질을 사용자가 직접 검토
~~~

## 12. 핵심 정리

### 핵심 개념

- LLM은 모든 지식을 저장해두고 검색하는 것이 아니라, 입력된 문맥을 토큰화하여 통계적 확률로 다음 토큰을 예측하는 방식으로 동작한다.
- AI 출력물의 환각 현상을 방지하기 위해 사용자는 명확한 제약 조건을 제공하는 컨텍스트 엔지니어링을 적용하고, 결과물을 직접 검증해야 한다.
- 작업의 성격에 맞추어 모델(GPT, Claude, Gemini 등)을 선별하고 적절한 도구들을 파이프라인으로 연결하는 툴 스택 구성이 효과적이다.

## 13. 느낀 점

생성형 AI를 단순히 정답을 찾아주는 검색 도구로 인식했으나, 토큰 분할과 임베딩 벡터 변환을 거쳐 확률적으로 문맥을 완성해 나가는 구조임을 체계적으로 파악했다. 특히 모델이 무제한으로 기억하는 것이 아니라 컨텍스트 윈도우라는 제약 속에서 동작한다는 점과, 통계적 추론의 특성상 환각이 발생할 수밖에 없다는 원리를 명확히 이해했다. 앞으로 AI를 실무에 도입할 때는 맹목적인 신뢰를 지양하고, 구체적인 제약 조건을 부여하는 프롬프트 구조화와 도구 연계를 통해 정확성을 직접 검증해 나가야 한다고 느꼈다.

# [TIL] Prompt Engineering, RAG, Fine-tuning, AI Agent

## 📝 오늘 배운 내용 요약

- **Prompt Engineering**은 지시문과 예시를 설계하여 모델 추가 학습 없이 LLM의 출력 방향과 형식을 조절하는 기법이다.
- **RAG**는 외부 문서나 데이터베이스에서 관련 정보를 검색한 후 LLM의 프롬프트에 맥락으로 제공하여 최신 정보 반영과 환각 완화를 돕는 방식이다.
- **Fine-tuning**은 특정 도메인 데이터로 사전 학습된 모델의 가중치를 추가 갱신하여 고유한 문체나 특정 작업 수행 능력을 특화하는 방법이다.
- **AI Agent**는 LLM이 주어진 목표에 따라 스스로 상황을 판단하고 외부 도구(API, 검색, DB 등)를 호출하여 복잡한 다단계 작업을 자율적으로 완수하는 시스템이다.

## 1. Prompt Engineering

### 개념 정의 및 목적

Prompt Engineering은 대형 언어 모델(LLM)에 입력하는 지시문(프롬프트)을 정교하게 설계하여 모델 추가 학습 없이 최적의 답변 결과를 얻어내는 기법이다. 모델의 파라미터를 변경하지 않고 역할 부여, 출력 형식 제한, 예시 제공 등을 통해 응답 품질을 통제하는 것을 목적으로 한다.

### 프롬프트 작성 예시

~~~text
너는 초보자에게 프로그래밍을 설명하는 선생님이다.
어려운 용어를 사용하지 말고 예시를 포함해서 설명해라.
~~~

- 모델에게 특정한 페르소나(선생님)를 지정한다.
- 쉬운 표현과 예시 포함이라는 명확한 제약 조건을 설정한다.

### 장점 및 고려사항

- **장점**:
  - 추가 인프라 구축이나 학습 비용이 발생하지 않는다.
  - 프롬프트 수정 즉시 결과를 확인하고 빠르게 테스트할 수 있다.
- **고려사항**:
  - 모델의 사전 학습 지식 범위를 근본적으로 확장하지는 못한다.
  - 모델별 입력 토큰(길이) 제한이 있어 방대한 양의 데이터를 한 번에 주입하기 어렵다.

## 2. RAG

### 개념 정의 및 동작 원리

RAG는 **Retrieval-Augmented Generation**의 약어로, 한국어로는 **검색 증강 생성**이라 한다. LLM이 자체 보유한 정적 지식에만 의존하지 않고, 외부 저장소에서 필요한 최신 정보나 내부 문서를 실시간으로 검색한 뒤 이를 LLM에게 프롬프트 문맥으로 제공하여 답변을 생성하도록 돕는 아키텍처이다.

~~~text
사용자 질문
    |
    v
관련 문서 검색 (외부 데이터베이스)
    |
    v
검색된 정보 + 사용자 질문 결합
    |
    v
LLM에게 전달
    |
    v
답변 생성
~~~

### RAG 파이프라인 구축 단계

RAG 시스템을 구축하기 위해서는 사전에 데이터를 준비하고 검색하는 파이프라인 설계가 요구된다.

~~~text
문서 수집
    |
    v
문서 분할 (Chunking)
    |
    v
임베딩 생성 (텍스트를 벡터로 변환)
    |
    v
벡터 DB 저장
    |
    v
사용자 질문 기반 유사도 검색
    |
    v
관련 문서 추출 후 LLM 전달
~~~

### 장점 및 고려사항

- **장점**:
  - 모델 재학습 없이 최신 데이터와 사내 보안 문서를 즉시 활용할 수 있다.
  - 검색된 출처 문서를 답변과 함께 제시할 수 있어 환각(Hallucination) 현상을 크게 줄인다.
- **고려사항**:
  - 텍스트 분할, 임베딩 모델 선택, 벡터 DB 구축 등 관리해야 할 시스템 구성 요소가 많다.
  - 검색 품질이 떨어지면 모델이 엉뚱한 맥락을 참고하여 답변 품질이 저하될 수 있다.

## 3. Fine-tuning

### 개념 정의 및 학습 흐름

Fine-tuning(미세 조정)은 이미 대규모 데이터로 사전 학습된(Pre-trained) 기본 모델에 특정 목적에 맞춘 데이터셋을 추가 학습시켜 모델 내부의 가중치(Weights)를 직접 업데이트하는 방법이다.

~~~text
기존 사전 학습 모델
    |
    v
특정 작업 전용 고품질 데이터셋 준비
    |
    v
추가 지도학습 진행 (가중치 갱신)
    |
    v
해당 작업에 특화된 전용 모델 완성
~~~

### 장점 및 고려사항

- **장점**:
  - 특정 산업군 전문 용어나 기업 고유의 문체, 고정된 출력 포맷을 일관되게 학습시킬 수 있다.
  - 프롬프트에 매번 긴 예시를 넣지 않아도 모델 자체의 작업 수행 능력이 향상된다.
- **고려사항**:
  - 정제된 고품질의 레이블링 데이터 확보가 필수적이다.
  - 모델 훈련에 필요한 GPU 컴퓨팅 자원과 시간 비용이 지속적으로 발생한다.
  - 데이터나 요구사항이 바뀌면 모델을 재학습해야 한다.

## 4. AI Agent

### 개념 정의 및 작동 구조

AI Agent는 LLM이 단순 텍스트 답변자 역할을 넘어 복잡한 목표를 스스로 분석하고, 다단계 계획을 수립하며, 필요한 외부 도구(Tool)를 직접 실행하여 작업을 완수하는 자율 제어 시스템이다.

~~~text
사용자 요청 ("이번 주 서울 날씨 확인 후 비 오는 날 알려줘")
    |
    v
LLM이 필요한 하위 작업 계획 수립
    |
    v
날씨 조회 API 도구 자동 호출
    |
    v
도구 반환 결과 확인 및 파싱
    |
    v
비 오는 날 필터링 및 추가 처리
    |
    v
최종 결과 답변
~~~

### 활용 가능한 외부 도구

- 웹 브라우징 검색 엔진
- 계산기 및 수식 연산 엔진
- 사내 RDB / NoSQL 데이터베이스 쿼리 도구
- 외부 서비스 연동 API
- 로컬 파일 입출력 및 코드 인터프리터(Python 등)

### 장점 및 고려사항

- **장점**:
  - 단일 입력-출력 구조로 해결 불가능한 복합 업무 프로세스를 자동화할 수 있다.
  - 도구의 실행 결과를 검토하고 실패 시 다른 방안을 시도하는 유연한 대처가 가능하다.
- **고려사항**:
  - 모델의 오판으로 인해 도구 호출 루프에 갇히는 무한 반복(Infinite Loop)이 발생할 수 있다.
  - 도구 실행 실패, 네트워크 오류 등에 대비한 예외 처리 및 명확한 종료 조건 설계가 필수적이다.

## 5. 비교 정리

### 네 가지 접근 방식 비교

| 구분 | 주요 개념 | 장점 | 고려사항 |
|---|---|---|---|
| `Prompt Engineering` | 지시문 및 예시로 LLM 출력 제어 | 즉각적인 적용 가능, 학습 비용 없음 | 모델 기본 지식 의존, 입력 길이 제한 |
| `RAG` | 외부 문서 및 DB 검색 결과를 프롬프트에 제공 | 최신 정보 반영, 환각 방지, 출처 제공 | 벡터 DB 등 별도 검색 인프라 구축 필요 |
| `Fine-tuning` | 특정 데이터셋으로 모델 가중치 추가 학습 | 특정 문체 및 포맷 특화, 일관성 확보 | 고품질 데이터 필요, 컴퓨팅 자원 및 재학습 비용 |
| `AI Agent` | LLM의 판단 기반 다단계 외부 도구 실행 | 복합 업무의 자율적 자동화 구현 | 실행 오류 제어, 무한 루프 방지 로직 필요 |

### 직관적 질문 관점 비교

- **Prompt Engineering**: "모델에게 어떻게 질문하고 지시할 것인가?"
- **RAG**: "모델이 답변할 근거 자료를 어디서 검색해 올 것인가?"
- **Fine-tuning**: "모델 자체를 특정 작업에 맞게 더 훈련시킬 것인가?"
- **AI Agent**: "모델이 스스로 판단하여 어떤 외부 도구를 사용하게 할 것인가?"

## 6. 기술 조합과 전체 흐름

### 기술의 복합적 결합 구조

네 가지 방식은 상호 배타적인 선택지가 아니며, 고도화된 AI 서비스 개발 시 상호 보완적으로 함께 구축된다.

~~~text
사용자 복합 질문
    |
    v
[AI Agent] 상황 판단 및 업무 분해
    |
    v
[RAG] 사내 벡터 DB에서 관련 근거 문서 검색
    |
    v
[Fine-tuned LLM] 사내 전용 어조로 튜닝된 모델에 전달
    |
    v
[Prompt Engineering] 구조화된 프롬프트 양식에 맞춰 최종 답변 생성
~~~

### 문제 유형별 해결 기법 선택 흐름

~~~text
[문제 상황 정의]
    |
    +---> 단순 답변 형식, 말투, 관점만 변경하고 싶은 경우
    |         |
    |         v
    |     Prompt Engineering 적용
    |
    +---> 최신 정보 반영 및 사내 문서 기반 검증이 필요한 경우
    |         |
    |         v
    |     RAG (검색 증강 생성) 구축
    |
    +---> 특정 전문 도메인 문체 고정 및 고유 태스크 수행 능력이 필요한 경우
    |         |
    |         v
    |     Fine-tuning (가중치 미세 조정) 진행
    |
    +---> 다단계 업무 처리와 외부 도구 연동 자동화가 필요한 경우
              |
              v
          AI Agent 시스템 설계
~~~

## 7. 핵심 정리

### 기술별 핵심 역할

- **Prompt Engineering**: 모델의 변경 없이 입력 지시문 최적화로 성능을 극대화한다.
- **RAG**: 동적 검색 엔진과 모델을 결합하여 환각 현상을 줄이고 정보의 최신성을 보장한다.
- **Fine-tuning**: 모델 파라미터를 직접 학습시켜 특화된 작업 처리 속도와 정확도를 향상한다.
- **AI Agent**: LLM을 두뇌로 삼아 외부 도구를 연동하고 작업을 연속적으로 자동 수행한다.

---

## 8. 느낀 점

Prompt Engineering, RAG, Fine-tuning, AI Agent가 모두 LLM을 활용하는 접근법이지만 각각이 해결하려는 병목 지점이 전혀 다르다는 점을 명확히 이해했다.
앞으로 AI 파이프라인을 설계할 때 해결하고자 하는 문제의 요구사항에 맞춰 네 가지 기술을 적절히 결합해 나가야겠다.

# 1. 핵심 개념

## LLM 애플리케이션 기본 구조

사용자의 입력을 모델에 그대로 전달하면 일관된 답변 형식을 얻기 어렵다.

따라서 입력을 템플릿에 주입하여 프롬프트를 완성하고, 완성된 프롬프트를 모델에 전달한 뒤, 모델의 응답 객체에서 필요한 데이터만 추출하는 파이프라인 구조를 사용한다.

## ChatPromptTemplate

대화형 언어 모델에 전달할 메시지 구조를 정의하는 템플릿이다.

- 고정된 지시문과 사용자가 입력할 동적 변수(`{변수명}`)를 분리하여 관리할 수 있다.
- 역할(Role)에 따라 메시지를 명확히 구분하여 모델에게 전달한다.

주요 메시지 역할:

- `system`: 모델의 페르소나, 역할, 제약 조건, 출력 형식 등을 사전에 지정한다.
- `user`: 실제 사용자가 전달하는 질문이나 요청 본문이다.
- `assistant`: 이전에 모델이 생성한 답변 내용이다.

## ChatOllama

로컬 환경에서 구동되는 Ollama 엔진의 언어 모델을 호출할 수 있도록 돕는 LangChain 인터페이스이다.

- 외부 API 서버 호출 없이 로컬 컴퓨터의 자원을 활용해 오픈소스 모델을 실행한다.
- 호출 결과로 문자열이 아닌 메시지 형태의 응답 객체를 반환한다.

## StrOutputParser

LLM 응답 객체에서 부가적인 메타데이터를 제외하고 순수한 텍스트 문자열만 추출하는 파서(Parser)이다.

- 모델의 원본 반환값은 메시지 객체 형태로 제공된다.
- 일반적인 애플리케이션 로직에서 텍스트를 다루기 위해 순수 문자열로 변환하는 작업이 필요하다.

## LCEL (LangChain Expression Language)

LangChain 컴포넌트를 파이프 연산자(`|`)로 연결하여 단일 파이프라인을 선언적으로 구축하는 문법이다.

- 각 구성 요소의 입출력 연결을 직관적으로 표현한다.
- 단계별로 `.invoke()`를 반복해서 호출하지 않고 전체 체인을 단 한 번의 실행으로 구동한다.

## 프롬프트 엔지니어링의 핵심 요소

- 목표 명확화: 모델이 수행해야 하는 핵심 과업을 구체적으로 전달한다.
- 제약 조건 부여: 답변 길이, 어조, 포함하거나 배제할 단어 등을 명시한다.
- 출력 규격 표준화: 원하는 결과 형식(JSON, 불릿 포인트, 문장 수 등)을 사전에 정의한다.

# 2. 실습 및 코드

## 개별 컴포넌트 호출 방식

각 컴포넌트를 생성하고 단계별로 실행하여 출력을 전달하는 방식이다.

~~~python
from langchain_core.prompts import ChatPromptTemplate
from langchain_ollama import ChatOllama
from langchain_core.output_parsers import StrOutputParser

# 1. 프롬프트 템플릿 생성
prompt_template = ChatPromptTemplate.from_messages([
    (
        'system',
        '당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 교육 전문가입니다. 2문장 이내로 친절하게 설명하세요.'
    ),
    ('user', '{user_question}')
])

# 2. 템플릿에 동적 변수 주입
sample_prompt = prompt_template.invoke({
    "user_question": "프로그래밍에서 '변수'가 무엇인가요?"
})

# 3. 로컬 모델 초기화 및 호출
model = ChatOllama(
    model="mistral",
    base_url="http://localhost:11434"
)
response = model.invoke(sample_prompt)

# 4. 출력 객체에서 문자열 추출
parser = StrOutputParser()
text = parser.invoke(response)

print(text)
~~~

- `ChatPromptTemplate.from_messages()`는 역할과 텍스트 쌍으로 대화 목록을 구성한다.
- `{user_question}` 자리에 딕셔너리로 넘겨준 값이 치환되어 프롬프트 객체가 완성된다.
- `model.invoke()`는 완성된 프롬프트를 모델에 넘겨 응답 객체를 생성한다.
- `parser.invoke()`는 응답 객체 내부의 텍스트 값만 추출하여 문자열 변수로 반환한다.

## LCEL을 이용한 체인 구성 방식

파이프 연산자(`|`)를 사용하여 입력부터 출력까지의 전체 파이프라인을 간결하게 결합한다.

~~~python
from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 1. 프롬프트 생성
prompt_template = ChatPromptTemplate.from_messages([
    (
        "system",
        "당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 교육 전문가입니다. "
        "2문장 이내로 친절하게 설명하세요."
    ),
    ("user", "{user_question}")
])

# 2. LLM 생성
model = ChatOllama(
    model="mistral",
    base_url="http://localhost:11434"
)

# 3. 출력 파서 생성
parser = StrOutputParser()

# 4. LCEL 체인 구성
chain = prompt_template | model | parser

# 5. 체인 실행
res = chain.invoke({
    "user_question": "클래스(Class)에 대해서 알기 쉬운 비유를 통해 설명하세요"
})

print(res)
~~~

- `prompt_template | model | parser` 구문으로 컴포넌트 간 데이터 전달 경로를 명시한다.
- 체인의 `.invoke()`를 호출하면 입력 딕셔너리가 템플릿에 주입되고, 모델을 거쳐 파싱된 최종 텍스트가 반환된다.

# 3. 비교 정리

## LLM 성능 확장 방식 비교

| 구분 | 주요 개념 | 장점 | 고려사항 |
|---|---|---|---|
| Prompt Engineering | 지시문과 예시만으로 모델의 출력을 제어 | 즉시 적용 가능하고 추가 인프라 비용이 적음 | 모델의 기본 지식과 입력 길이 제한에 의존 |
| RAG | 외부 문서나 DB를 검색하여 프롬프트에 첨부 | 최신 정보 반영, 출처 기반 답변 가능 | 검색 시스템과 문서 처리 파이프라인 필요 |
| Fine-tuning | 특정 데이터셋으로 모델 가중치를 추가 학습 | 고유한 문체와 특화된 형식의 준수율 향상 | 고품질 학습 데이터와 재학습 비용 필요 |
| AI Agent | LLM이 판단하여 검색·계산 등의 외부 도구를 실행 | 복잡한 다단계 업무 자동화 가능 | 실행 루프와 도구 오류에 대한 예외 처리 필요 |

- 단순 지시문 설계는 프롬프트 엔지니어링 단계에 해당한다.
- 최신 정보 검색은 RAG를 통해 외부 데이터를 프롬프트에 결합한다.
- 특화된 도메인 스타일 습득은 가중치를 조정하는 파인튜닝을 적용한다.
- 도구를 활용한 자율적인 문제 해결은 AI 에이전트 구조로 확장한다.

# 4. 전체 흐름 정리

## LLM 애플리케이션 파이프라인

~~~text
사용자 입력
    |
    v
ChatPromptTemplate (템플릿 변수 주입 및 메시지 구조화)
    |
    v
ChatOllama (LLM 호출 및 응답 객체 생성)
    |
    v
StrOutputParser (응답 객체에서 순수 문자열 추출)
    |
    v
최종 답변 문자열
~~~

## LLM 기능 확장 발전 흐름

~~~text
Prompt Engineering (지시문 작성 및 형식 제어)
    |
    v
RAG (외부 지식 검색 및 결합)
    |
    v
Fine-tuning (도메인 특화 모델 가중치 재학습)
    |
    v
AI Agent (도구 사용 및 다단계 의사결정 자동화)
~~~

# 5. 핵심 정리

## 핵심 코드

~~~python
chain = prompt_template | model | parser
res = chain.invoke({"user_question": "질문 내용"})
~~~

- 파이프 연산자(`|`)로 컴포넌트를 연결하여 단일 체인을 생성한다.
- 체인에 질문을 딕셔너리 형태로 전달하여 최종 문자열 출력을 도출한다.

## 핵심 개념

- 대화형 모델은 `system`, `user`, `assistant` 역할을 명확히 분리하여 입력 구조를 설계해야 한다.
- 모델의 직접 출력은 객체 형태이므로 애플리케이션에서 사용하기 위해 `StrOutputParser`와 같은 파서를 거쳐야 한다.
- LCEL은 단계별 호출 코드를 간소화하고 전체 데이터 흐름의 가독성을 높여준다.
- 프롬프트 설계는 단순 질문 전달을 넘어 목표, 제약 조건, 출력 규격을 포함해야 한다.

# 6. 느낀 점

이번 학습을 통해 LLM을 단순히 호출하는 것을 넘어 프롬프트 템플릿, 모델, 파서를 연결하여 하나의 체인으로 구성하는 구조를 정리했다. 단계별 호출 방식을 LCEL 파이프라인으로 단순화하는 방식을 직접 실습하며 파이프라인 연결의 직관성을 파악할 수 있었다. 프롬프트 엔지니어링부터 AI 에이전트까지 이어지는 확장 개념을 분류해 보며 향후 RAG나 도구 활용 방식으로 발전시키는 기준을 정리했다.

# 1장 3강: 테이블 간 관계와 ERD 읽기

## 📌 학습 목표

- 1:1 / 1:N / N:M 관계 유형을 구분할 수 있다.
- 각 관계 유형의 실무 예시를 이해할 수 있다.
- ERD(Entity Relationship Diagram)의 기본 구성 요소를 이해할 수 있다.
- Crow's Foot 표기법을 읽을 수 있다.

---

## 1. 테이블 간 관계

관계형 데이터베이스에서는 여러 테이블이 서로 연결되어 하나의 데이터 구조를 구성한다.

테이블 간 관계는 크게 다음 세 가지로 나눌 수 있다.

- **1:1 관계**
- **1:N 관계**
- **N:M 관계**

관계의 유형은 한 테이블의 하나의 레코드가 다른 테이블의 몇 개의 레코드와 연결될 수 있는지를 기준으로 구분한다.

---

## 2. 1:1 관계

### 개념

**1:1(일대일) 관계**는 한 테이블의 하나의 레코드가 다른 테이블의 하나의 레코드와 연결되는 관계이다.

```text
회원 1 ─── 1 회원상세정보
```

예를 들어 회원과 회원 상세정보가 1:1 관계라면,

- 회원 한 명 → 하나의 회원 상세정보
- 회원 상세정보 하나 → 한 명의 회원

으로 연결된다.

### 실무 예시

```text
members
- user_id
- name

member_details
- member_id
- address
- birth_date
```

회원의 기본 정보와 상세 정보를 분리하여 관리할 때 사용할 수 있다.

### 특징

- 하나의 데이터가 다른 테이블의 하나의 데이터와 연결된다.
- 데이터 보안이나 관리 목적에 따라 테이블을 분리할 때 사용할 수 있다.

---

## 3. 1:N 관계

### 개념

**1:N(일대다) 관계**는 한 테이블의 하나의 레코드가 다른 테이블의 여러 레코드와 연결되는 관계이다.

```text
회원 1 ─── N 주문
```

예를 들어 한 명의 회원은 여러 개의 주문을 할 수 있다.

하지만 하나의 주문은 한 명의 회원에게만 속한다.

```text
회원
회원ID = 1

    ↓

주문
주문ID = 101
주문ID = 102
주문ID = 103
```

### 실무 예시

#### 회원 : 주문

```text
members
- member_id
- name

orders
- order_id
- member_id
- order_date
```

한 명의 회원이 여러 번 주문할 수 있으므로

```text
members 1 ─── N orders
```

관계가 된다.

#### 게시글 : 댓글

```text
게시글 1 ─── N 댓글
```

하나의 게시글에는 여러 개의 댓글이 달릴 수 있지만, 하나의 댓글은 하나의 게시글에 속한다.

### 특징

실무에서 가장 자주 등장하는 관계 유형이다.

```text
부서 1 ─── N 직원
회원 1 ─── N 주문
게시글 1 ─── N 댓글
카테고리 1 ─── N 상품
```

---

## 4. N:M 관계

### 개념

**N:M(다대다) 관계**는 양쪽 테이블의 하나의 레코드가 서로 여러 개의 레코드와 연결될 수 있는 관계이다.

```text
학생 N ─── M 강의
```

예를 들어,

- 한 명의 학생은 여러 강의를 수강할 수 있다.
- 하나의 강의에는 여러 학생이 수강할 수 있다.

따라서 학생과 강의는 N:M 관계이다.

---

## 5. N:M 관계와 중간 테이블

관계형 데이터베이스에서는 N:M 관계를 직접 표현하기보다는 **중간 테이블(Junction Table)**을 사용하여 두 개의 1:N 관계로 분리한다.

### 예시

```text
학생
- student_id
- name

강의
- course_id
- title

수강
- student_id
- course_id
```

관계를 다음과 같이 표현할 수 있다.

```text
학생 1 ─── N 수강 N ─── 1 강의
```

즉,

```text
학생 : 수강 = 1:N
강의 : 수강 = 1:N
```

으로 분리한다.

### 왜 중간 테이블이 필요한가?

학생 테이블에 수강하는 강의를 여러 개 저장하거나, 강의 테이블에 수강하는 학생을 여러 명 저장하면 데이터가 복잡해지고 중복이 발생할 수 있다.

따라서 별도의 수강 테이블을 만들어 관계를 관리한다.

---

## 6. 관계 유형 비교

| 관계 유형 | 의미 | 실무 예시 |
|---|---|---|
| **1:1** | 하나 ↔ 하나 | 회원 : 회원 상세정보 |
| **1:N** | 하나 ↔ 여러 개 | 회원 : 주문 |
| **N:M** | 여러 개 ↔ 여러 개 | 학생 : 강의 |

### 핵심 차이

```text
1:1
회원 1 ─── 1 회원상세

1:N
회원 1 ─── N 주문

N:M
학생 N ─── M 강의
        ↓
      수강
```

특히 **N:M 관계는 중간 테이블을 사용한다**는 점이 중요하다.

---

## 7. ERD란?

**ERD(Entity Relationship Diagram)**는 데이터베이스의 테이블과 테이블 사이의 관계를 시각적으로 표현한 다이어그램이다.

복잡한 데이터베이스의 구조를 한눈에 파악할 수 있기 때문에 실무에서 데이터베이스 구조를 이해할 때 자주 사용한다.

---

## 8. ERD의 기본 구성 요소

ERD의 핵심 구성 요소는 다음과 같다.

### ① 엔티티(Entity)

데이터베이스의 **테이블**에 해당한다.

```text
┌──────────────┐
│    members   │
├──────────────┤
│ member_id    │
│ name         │
│ email        │
└──────────────┘
```

### ② 속성(Attribute)

테이블의 **컬럼(Column)**에 해당한다.

예:

```text
member_id
name
email
```

### ③ 관계(Relationship)

테이블과 테이블 사이의 연결을 의미한다.

```text
members 1 ─── N orders
```

---

## 9. Crow's Foot 표기법

ERD에서는 테이블 간 관계의 수량을 나타내기 위해 **Crow's Foot Notation(까마귀발 표기법)**을 사용한다.

주요 기호는 다음과 같다.

| 기호 | 의미 |
|---|---|
| `|` | 1개 |
| `O` | 0개, 선택적 |
| `<` | 여러 개(N) |
| `||` | 정확히 1개 |
| `O<` | 0개 이상 |
| `|<` | 1개 이상 |

---

## 10. ERD 관계 읽는 방법

예를 들어 다음과 같은 관계가 있다고 하자.

```text
회원 || ───── O< 주문
```

이를 양쪽 방향으로 읽어야 한다.

### 회원 → 주문

```text
회원 || ───── O< 주문
```

회원 한 명은 **0개 이상의 주문**을 가질 수 있다.

즉,

```text
회원 1 ─── 0..N 주문
```

### 주문 → 회원

주문 하나는 반드시 하나의 회원에게 속한다.

즉,

```text
주문 N ─── 1 회원
```

따라서 전체 관계는

```text
회원 1 ─── N 주문
```

인 **1:N 관계**이다.

---

## 11. ERD를 읽는 순서

ERD가 복잡할 때는 한 번에 전체를 이해하려고 하지 않는 것이 좋다.

### ① 중심 테이블 찾기

가장 많은 테이블과 연결되어 있는 테이블을 먼저 찾는다.

예:

```text
             상품
              │
              │
회원 ───── 주문 ───── 결제
              │
              │
            배송
```

이 경우 `주문` 테이블을 중심으로 다른 테이블과의 관계를 확인할 수 있다.

### ② 연결된 테이블 확인

중심 테이블에서 연결된 테이블을 하나씩 확인한다.

```text
회원 → 주문
주문 → 결제
주문 → 배송
주문 → 상품
```

### ③ 관계의 기호 확인

선의 양쪽에 있는 기호를 확인한다.

```text
회원 || ───── O< 주문
```

다음과 같이 질문하면 이해하기 쉽다.

> "회원 한 명은 주문을 몇 개 가질 수 있는가?"

→ 0개 이상

> "주문 하나는 회원을 몇 명 가질 수 있는가?"

→ 정확히 1명

### ④ 관계 유형 판단

마지막으로 1:1, 1:N, N:M 중 어떤 관계인지 판단한다.

---

## 12. 실무 예시로 정리

### 회원과 주문

```text
회원 1 ─── N 주문
```

한 명의 회원이 여러 주문을 할 수 있으므로 **1:N 관계**이다.

### 게시글과 댓글

```text
게시글 1 ─── N 댓글
```

하나의 게시글에 여러 댓글이 달릴 수 있으므로 **1:N 관계**이다.

### 학생과 강의

```text
학생 N ─── M 강의
```

학생도 여러 강의를 듣고 강의도 여러 학생을 가질 수 있으므로 **N:M 관계**이다.

따라서 중간 테이블이 필요하다.

```text
학생 1 ─── N 수강 N ─── 1 강의
```

---

## 13. 이번 강의에서 알게 된 것

- 데이터베이스의 테이블은 서로 관계를 맺을 수 있다.
- 테이블 간 관계는 **1:1, 1:N, N:M**으로 구분한다.
- **1:1**은 하나의 데이터가 다른 하나의 데이터와 연결되는 관계이다.
- **1:N**은 하나의 데이터가 여러 데이터와 연결되는 관계이다.
- **N:M**은 양쪽 모두 여러 데이터와 연결되는 관계이다.
- N:M 관계는 관계형 데이터베이스에서 **중간 테이블**을 사용하여 두 개의 1:N 관계로 분리한다.
- ERD는 데이터베이스의 테이블과 관계를 시각적으로 표현한 다이어그램이다.
- ERD의 엔티티는 테이블, 속성은 컬럼, 관계는 테이블 간 연결을 의미한다.
- Crow's Foot 표기법을 사용하면 테이블 간 데이터의 연결 개수를 파악할 수 있다.
- ERD를 읽을 때는 중심 테이블을 찾고, 연결된 테이블을 하나씩 따라가면서 관계를 확인하는 것이 좋다.

---

## 💡 핵심 암기

```text
1:1 → 하나 ↔ 하나

1:N → 하나 ↔ 여러 개
     예) 회원 : 주문
         게시글 : 댓글

N:M → 여러 개 ↔ 여러 개
     예) 학생 : 강의
     → 중간 테이블 필요
```

**가장 중요한 것은 `1:N`과 `N:M`의 차이이다.**

```text
1:N
회원 1 ─── N 주문
→ 주문 하나는 한 회원에게만 속함

N:M
학생 N ─── M 강의
→ 중간 테이블을 사용하여 분리
→ 학생 1 ─── N 수강 N ─── 1 강의
```

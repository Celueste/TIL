# [TIL] 데이터베이스 정규화와 SQL 기초 (DDL, DML, TCL)

## 📌 오늘 배운 내용
- **데이터베이스 정규화 (1NF ~ 3NF)**: 중복 제거 및 무결성 확보를 위한 단계적 테이블 분리 원칙과 반정규화 고려
- **SQL 명령어 4대 분류**: DDL(구조 정의), DML(데이터 조작), DCL(권한 제어), TCL(트랜잭션 제어)
- **테이블 생성 및 조작 실습**: PostgreSQL 기준 `CREATE TABLE`, `INSERT INTO`, 기본키 자동증감(`SERIAL`) 문법

---

## 1. 상세 내용

### 1-1. 데이터베이스 정규화 (Normalization)
- **정규화 목적**: 데이터 중복 최소화 및 무결성 향상. 이상 현상(갱신 이상, 삽입 이상, 삭제 이상) 방지.
- **정규화 단계**:
  - **1NF (제1정규형)**: 모든 컬럼에 단 하나의 값만 저장 (원자값 보장).
  - **2NF (제2정규형)**: 복합키의 일부에만 의존하는 부분 함수 종속 제거 (완전 함수 종속 만족).
  - **3NF (제3정규형)**: PK가 아닌 일반 컬럼 간의 이행적 종속 제거 (`A -> B -> C` 구조 분리).
- **반정규화(De-normalization)**: 정규화가 지나치면 `JOIN` 연산 비용이 증가하므로 성능을 고려해 의도적으로 일부 중복 허용.

### 1-2. SQL 명령어 분류 및 차이
- **DDL (Data Definition Language)**: 데이터 구조 정의/변경/삭제
  - `CREATE`, `ALTER`, `DROP`
  - `TRUNCATE`: 테이블 구조는 유지한 채 데이터 전체를 고속 초기화.
- **DML (Data Manipulation Language)**: 데이터 조회/삽입/수정/삭제
  - `SELECT` (DQL), `INSERT`, `UPDATE`, `DELETE`
- **DCL (Data Control Language)**: 권한 제어
  - `GRANT` (권한 부여), `REVOKE` (권한 회수)
- **TCL (Transaction Control Language)**: 트랜잭션 작업 제어
  - `COMMIT` (DB 영구 반영), `ROLLBACK` (직전 commit 상태로 취소 복구)

### 1-3. PostgreSQL DDL / DML 문법 및 실습
- **제약 조건**:
  - `PRIMARY KEY`: 중복 불가, `NULL` 불가
  - `NOT NULL`: 빈 값 허용 안 함
  - `UNIQUE`: 중복 허용 안 함 (`NULL`은 허용)
  - `DEFAULT`: 미입력 시 기본값 지정
  - `REFERENCES`: 외래키 참조 무결성 보장 (부모에 없는 값 사용 불가)
- **기본키 자동증감**:
  - 표준: `INT GENERATED ALWAYS AS IDENTITY`
  - PostgreSQL: `SERIAL` (4byte), `BIGSERIAL` (8byte)
- **테이블 생성 예제 (`CREATE TABLE`)**:
  ```sql
  CREATE TABLE products (
      product_id   INT            PRIMARY KEY,
      product_name VARCHAR(100)   NOT NULL,
      price        DECIMAL(10, 2) NOT NULL,
      category     VARCHAR(50),
      created_at   DATE           NOT NULL
  );
  ```
- **데이터 입력 예제 (`INSERT INTO`)**:
  - 컬럼명을 명시하는 것이 순서 변경 및 오류 방지에 안전함.
  - 다중 행 일괄 삽입(Multi-row INSERT):
  ```sql
  INSERT INTO products (product_id, product_name, price, category, created_at)
  VALUES
      (1, '노트북 파우치', 25000.00, '가방', '2024-01-10'),
      (2, '무선 마우스',   35000.00, '전자기기', '2024-01-15'),
      (3, '볼펜 세트',      8000.00, '문구', '2024-01-20');
  ```
- **테이블 확인 및 삭제**:
  - 구조 확인: `\d 테이블명` (psql)
  - 삭제: `DROP TABLE 테이블명;` (복구 불가)

## 2. 오늘의 회고
- **새롭게 알게 된 점**:
  - `DROP`, `TRUNCATE`, `DELETE`의 차이점: `DROP`은 테이블 자체를 삭제하고, `TRUNCATE`는 DDL로 구조를 남기며 고속 초기화하며, `DELETE`는 DML로서 조건부 삭제 및 트랜잭션 롤백이 가능함.
  - PostgreSQL에서 자동증감 키를 다룰 때 `SERIAL` 외에도 표준 문법인 `GENERATED ALWAYS AS IDENTITY`를 사용할 수 있다는 점.
- **어려웠던 부분 및 해결**:
  - 복합키에서의 부분 함수 종속(2NF)과 일반 컬럼 간 이행 종속(3NF) 구분이 헷갈렸으나, "PK의 일부에 걸려 있는가" vs "일반 컬럼끼리 물려 있는가"로 기준을 명확히 정리함.
- **향후 계획**:
  - 외래키 제약조건(`REFERENCES`)을 적용한 다중 테이블 간 관계 설계와 `JOIN` 조회 쿼리 실습 진행하기.

## 💡 핵심 요약
- 정규화는 중복을 줄이고 이상 현상을 방지하기 위한 분리 과정이며, 조회 성능을 위해 적절한 반정규화 균형이 필요하다.
- DDL은 구조를 만들고(CREATE/DROP/TRUNCATE), DML은 데이터를 다루며(INSERT/UPDATE/DELETE), TCL(COMMIT/ROLLBACK)로 작업의 영구 반영 여부를 결정한다.
- 외래키 참조 무결성은 부모에 없는 값을 자식이 가질 수 없도록 보장하며, 데이터 타입 불일치 시 DB가 즉시 입력을 차단한다.

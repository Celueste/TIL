# 1. 핵심 개념

## 서브쿼리 기본

서브쿼리는 하나의 SQL 문장 안에 포함된 또 다른 `SELECT` 구문을 의미한다.

서브쿼리를 감싸고 있는 바깥쪽 구문을 외부 쿼리(Outer Query)라 부르고, 괄호 `()` 안에 작성되어 먼저 실행되는 내부 구문을 서브쿼리(Inner Query)라 부른다.

고정된 상숫값이 아니라 다른 테이블의 집계 결과나 조회 데이터를 바탕으로 조건을 동적으로 구성해야 할 때 사용한다.

## 작성 위치에 따른 서브쿼리 종류

### WHERE 절 서브쿼리
- 조건식의 기준값을 사전에 계산하거나 필터링할 목록을 동적으로 가져올 때 사용한다.
- 단일 행 연산자(`>`, `<`, `=`)와 함께 쓸 때는 서브쿼리가 하나의 값만 반환해야 한다.
- 복수 행 결과를 다룰 때는 `IN`, `NOT IN`, `EXISTS`, `NOT EXISTS`와 같은 다중 행 연산자를 조합한다.

### FROM 절 서브쿼리 (인라인 뷰)
- 서브쿼리의 조회 결과를 하나의 가상 임시 테이블처럼 활용하는 방식이다.
- 테이블 전체를 대상으로 1차 가공(그룹 집계, 계산 등)을 마친 뒤, 그 결과에 다시 필터링을 걸거나 다른 테이블과 연결할 때 유용하다.
- PostgreSQL을 비롯한 대다수 데이터베이스에서는 `FROM` 절 서브쿼리에 반드시 별칭(Alias)을 부여해야 한다.

### SELECT 절 서브쿼리 (스칼라 서브쿼리)
- `SELECT` 절에서 조회할 컬럼 중 하나로 사용되는 서브쿼리이다.
- 각 행마다 정확히 하나의 값(단일 행, 단일 열)만 반환해야 한다.
- 서브쿼리의 결과가 둘 이상의 행이거나 둘 이상의 컬럼이면 실행 시 오류가 발생한다.

## 데이터 확인 연산자

### IN과 NOT IN
- 서브쿼리가 반환하는 여러 값의 목록과 외부 쿼리의 컬럼 값을 직접 비교한다.
- `IN`은 서브쿼리 결과 목록 중 일치하는 값이 하나라도 있으면 해당 행을 채택한다.
- `NOT IN`은 서브쿼리 결과 목록에 없는 데이터만 채택한다.
- 서브쿼리 결과 집합에 `NULL`이 하나라도 포함되어 있으면 `NOT IN`의 논리 연산 결과가 참이 되지 않아 의도치 않게 전체 조회가 누락될 수 있다.

### EXISTS와 NOT EXISTS
- 실제 값을 비교하는 대신, 서브쿼리 조건에 부합하는 레코드가 최소 한 행이라도 존재하는지 여부만 검증한다.
- 서브쿼리 조건에 맞는 데이터가 한 건이라도 발견되면 즉시 참을 반환하고 서브쿼리 실행을 멈춘다.
- 레코드의 존재 유무만 확인하므로 `SELECT 1`과 같이 단순화된 조회식을 관례적으로 사용한다.

## 상관 서브쿼리

서브쿼리 내부 조건절에서 바깥쪽 외부 쿼리의 컬럼을 직접 참조하는 형태를 의미한다.

외부 쿼리의 각 행이 평가될 때마다 해당 행의 컬럼 값을 서브쿼리에 전달하여 연산을 반복 수행한다.

# 2. 실습 및 코드

## WHERE 절을 통한 동적 기준값 필터링

~~~sql
SELECT product_id, product_name, list_price
FROM products
WHERE list_price > (
    SELECT AVG(list_price)
    FROM products
);
~~~

- `products` 테이블에서 상품 식별자, 상품명, 가격을 조회한다.
- 괄호 안의 서브쿼리가 전체 상품의 평균 가격(`AVG(list_price)`)을 먼저 단일 값으로 계산한다.
- 외부 쿼리는 계산된 평균값을 전달받아 가격이 그보다 높은 상품 행만 필터링하여 반환한다.

## 목록 비교 (IN과 NOT IN)

~~~sql
SELECT customer_id, first_name, last_name
FROM customers
WHERE customer_id IN (
    SELECT DISTINCT customer_id
    FROM orders
);
~~~

- `customers` 테이블의 고객 정보를 대상으로 조회한다.
- 서브쿼리에서 `orders` 테이블에 존재하는 중복 없는 고객 식별자 목록을 추출한다.
- `IN` 연산자를 사용하여 실제 주문 이력이 존재하는 고객만 선별한다.

~~~sql
SELECT customer_id, first_name, last_name
FROM customers
WHERE customer_id NOT IN (
    SELECT DISTINCT customer_id
    FROM orders
);
~~~

- 서브쿼리가 생성한 주문 고객 식별자 목록에 포함되지 않은 고객을 찾는다.
- 주문 이력이 없는 고객 데이터를 조회할 때 활용한다.

## 존재 여부 검증 (EXISTS와 NOT EXISTS)

~~~sql
SELECT c.customer_id, c.first_name, c.last_name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
~~~

- 고객 테이블(`customers c`)의 각 행마다 `customer_id`를 서브쿼리로 넘겨 주문 테이블(`orders o`)과의 일치 행을 찾는다.
- 만족하는 레코드가 적어도 1건 존재하면 참으로 판정하여 해당 고객을 조회 목록에 포함한다.
- `SELECT 1`은 특정 컬럼 값이 아닌 행의 존재 여부만 확인하기 위한 표현이다.

~~~sql
SELECT c.customer_id, c.first_name, c.last_name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
~~~

- 서브쿼리의 조건(`o.customer_id = c.customer_id`)에 부합하는 주문 데이터가 전혀 없는 고객만 참으로 판별하여 조회한다.

## FROM 절 인라인 뷰

~~~sql
SELECT customer_id, total_amount
FROM (
    SELECT customer_id, SUM(amount) AS total_amount
    FROM orders
    GROUP BY customer_id
) AS customer_totals
WHERE total_amount >= 1000000;
~~~

- `FROM` 절 내부의 서브쿼리는 `orders` 테이블에서 고객별 누적 주문 금액(`SUM(amount)`)을 집계한다.
- 서브쿼리 결과에 `customer_totals`라는 별칭을 주어 하나의 임시 집계 테이블로 다룬다.
- 외부 쿼리는 이 임시 집계 테이블에서 누적 금액(`total_amount`)이 1,000,000 이상인 고객만 필터링하여 출력한다.

## SELECT 절 스칼라 서브쿼리와 상관 서브쿼리

~~~sql
SELECT
    product_id,
    product_name,
    list_price,
    (
        SELECT AVG(list_price)
        FROM products
    ) AS avg_price
FROM products;
~~~

- 각 상품의 개별 정보와 함께 전체 상품의 가격 평균값을 동일한 행에 나란히 배치한다.
- 서브쿼리가 단 하나의 단일 평균값을 반환하므로 `avg_price`라는 가상 컬럼 역할을 수행한다.

~~~sql
SELECT
    c.customer_id,
    c.first_name,
    c.last_name,
    (
        SELECT COUNT(*)
        FROM orders o
        WHERE o.customer_id = c.customer_id
    ) AS order_count
FROM customers c;
~~~

- 서브쿼리가 외부 쿼리의 고객 식별자(`c.customer_id`)를 조건식으로 참조하는 상관 서브쿼리이다.
- 각 고객 행마다 매칭되는 주문 건수를 서브쿼리에서 계산하여 `order_count` 열로 매핑한다.

# 3. 비교 정리

## 목록 비교 연산자 비교

| 구분 | `IN` | `EXISTS` |
|---|---|---|
| 검증 방식 | 서브쿼리가 추출한 값 목록과의 직접 비교 | 조건에 일치하는 행의 존재 유무 검증 |
| 처리 특성 | 결과 목록을 구성하여 포함 여부를 확인 | 조건 만족 행 확인 시 탐색 즉시 중단 |
| NULL 처리 | `NOT IN` 사용 시 서브쿼리 내 `NULL` 주의 필요 | 행의 존재 여부만 따지므로 `NULL` 영향 없음 |
| 주 용도 | 명확한 단일 컬럼 값 목록 대조 | 연관 테이블의 매칭 데이터 유무 확인 |

## 서브쿼리와 JOIN의 특성 비교

| 구분 | 서브쿼리 | `JOIN` |
|---|---|---|
| 결과 형태 | 메인 테이블의 구조를 유지하며 필터링 | 여러 테이블의 컬럼을 가로로 확장 결합 |
| 작성 목적 | 단일 계산값 주입 및 조건부 존재 확인 | 복수 테이블의 상세 컬럼을 동시 조회 |
| 주 사용처 | 인라인 뷰 집계, 단순 존재성(`EXISTS`) 확인 | 테이블 간 관계 표현 및 복합 데이터 출력 |

# 4. 전체 흐름 정리

## FROM 절 인라인 뷰 실행 구조

~~~text
orders 테이블 원본
        |
        v
고객별 주문 금액 집계 (GROUP BY)
        |
        v
인라인 뷰 임시 가상 테이블 생성
        |
        v
WHERE 절 조건 필터링 (total_amount >= 1,000,000)
        |
        v
최종 결과 출력
~~~

## 상관 서브쿼리 데이터 전달 구조

~~~text
외부 쿼리의 customers 레코드 순회
        |
        v
현재 고객의 customer_id 전달
        |
        v
서브쿼리가 해당 customer_id의 주문 건수 집계
        |
        v
계산된 값을 order_count 열에 할당
~~~

# 5. 핵심 정리

## 핵심 코드

~~~sql
SELECT c.customer_id, c.first_name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
~~~

- 외부 쿼리의 식별자를 넘겨 연관 데이터가 존재하는 행만 효율적으로 추출한다.

~~~sql
SELECT customer_id, total_amount
FROM (
    SELECT customer_id, SUM(amount) AS total_amount
    FROM orders
    GROUP BY customer_id
) AS customer_totals
WHERE total_amount >= 1000000;
~~~

- 1차 집계 결과를 `FROM` 절의 인라인 뷰로 구성하여 별칭을 붙이고 외부에서 재필터링한다.

## 핵심 개념

- 서브쿼리는 괄호 `()`로 묶인 중첩 `SELECT` 문이며, 외부 쿼리의 조건 계산이나 가상 테이블 역할을 한다.
- `WHERE` 절 서브쿼리는 계산된 단일 값이나 복수 목록을 조건식에 제공한다.
- `NOT IN`을 사용할 때는 서브쿼리 결과에 `NULL`이 포함되어 있는지 확인해야 하며, 데이터 존재 유무 확인에는 `EXISTS`가 안정적이다.
- `FROM` 절 서브쿼리는 인라인 뷰 역할을 수행하며 데이터베이스 엔진에 따라 별칭 부여가 필수이다.
- `SELECT` 절 스칼라 서브쿼리는 결과값이 반드시 단 하나의 행과 단 하나의 열이어야 한다.
- 외부 쿼리의 컬럼을 내부 서브쿼리에서 참조하면 행 단위로 반복 평가되는 상관 서브쿼리가 된다.

# 6. 느낀 점

SQL 쿼리 내부에 `SELECT` 문을 중첩하여 조건이나 연산 결과를 유연하게 활용하는 서브쿼리의 동작 구조를 정리했다. 작성 위치에 따라 `WHERE` 절 조건 필터, `FROM` 절 인라인 뷰, `SELECT` 절 스칼라 서브쿼리로 나뉘는 기준을 파악했다. 특히 단순 값 목록을 비교하는 `IN`과 행의 존재 유무만 확인하는 `EXISTS`의 차이를 구분하고, `NOT IN` 사용 시 `NULL` 처리에 유의해야 한다는 점을 확인했다. 아울러 다중 테이블 데이터를 결합할 때 서브쿼리와 `JOIN`이 상호 대체될 수 있는 환경에서 데이터 구조와 목적에 맞게 적절한 방식을 선택해야 함을 익혔다.

## 1. 데이터 사이언티스트에게 SQL이 필수적인 이유
* **자립적인 데이터 탐색 및 추출**: 개발자나 데이터 엔지니어에게 매번 요청하지 않고, 필요한 비즈니스 데이터를 직접 조회·추출·가공 가능
* **모델링 품질 결정**: 머신러닝 모델의 성능은 알고리즘뿐만 아니라 입력 피처(Feature)를 어떻게 추출하고 구성하느냐에 직결됨
* **데이터 사이언티스트 핵심 4대 역량**:
  1. `SQL`: 데이터 추출 및 가공
  2. `Python`: 데이터 전처리, 시각화, ML 모델링
  3. `통계/머신러닝`: 예측 및 패턴 파악
  4. `비즈니스 커뮤니케이션`: 결과 전달 및 문제 해결

## 2. 데이터베이스 기초 및 관계형 DB(RDBMS)

### ① 기본 개념
* **Data**: 원시 값 (Raw Value)
* **Database (DB)**: 체계적으로 정리된 데이터 집합
* **DBMS**: 데이터베이스를 생성·운영·관리하는 소프트웨어 (PostgreSQL, MySQL, Oracle 등)
* **Query / SQL**: 질의(명령문) 및 데이터 조작을 위한 표준화된 언어

### ② 관계형 DB 핵심 구조
* **테이블(Table)**: 행과 열로 이루어진 2차원 데이터 집합
* **행(Row / Record)**: 개별 데이터 항목 (예: 특정 회원 1명의 정보)
* **열(Column / Field)**: 데이터의 공통 속성 (예: 이름, 이메일, 가입일)
* **셀(Cell)**: 행과 열이 교차하는 최소 저장 단위

### ③ DBMS(Database Management System) 개념 및 종류

* DBMS는 데이터베이스를 생성, 관리, 제어, 운영하는 소프트웨어로 사용자와 데이터베이스 사이의 통역사 역할을 수행합니다.

### ④ SQL 작성 순서 vs 실제 실행 순서
쿼리 실행 시 논리적 처리 순서를 알아야 별칭(Alias) 참조 오류나 조건식 에러를 방지할 수 있습니다.

| 단계 | 작성 순서 (Syntax) | 실제 실행 순서 (Execution) |
| :--- | :--- | :--- |
| 1 | **SELECT** | **FROM** |
| 2 | **FROM** | **WHERE** |
| 3 | **WHERE** | **GROUP BY** |
| 4 | **GROUP BY** | **HAVING** |
| 5 | **HAVING** | **SELECT** |
| 6 | **ORDER BY** | **ORDER BY** |

> **실행 순서 핵심 포인트**: `WHERE` 절은 `SELECT` 절보다 먼저 실행되므로, `SELECT`에서 정의한 별칭(Alias)은 `WHERE` 절에서 필터 조건으로 사용할 수 없습니다.

## 3. 데이터 무결성 제약조건 (Data Integrity)

1. **도메인 무결성 (Domain Integrity)**: 컬럼에 지정된 자료형, 길이, 널(NULL) 허용 여부 등의 규칙을 만족해야 함
2. **개체 무결성 (Entity Integrity)**: 테이블 내 모든 행을 고유하게 식별할 수 있도록 기본키(PK)는 고유해야 하며 `NULL` 값을 가질 수 없음
3. **참조 무결성 (Referential Integrity)**: 외래키(FK) 값은 참조하는 부모 테이블의 PK 값과 일치하거나 `NULL`이어야 함 (존재하지 않는 부모 데이터를 참조 불가)

## 4. 데이터 타입 (Data Types)

### ① 숫자형 (Numeric)
* `smallint` (2byte), `int` (4byte), `bigint` (8byte)
* `real` (4byte 부동소수점), `double precision` (8byte 부동소수점)
* `decimal(p, s)` / `numeric(p, s)`: 전체 자릿수 `p`, 소수점 자릿수 `s`의 고정소수점 (금융 데이터 필수)

### ② 문자형 (Character)
* `char(n)`: 고정 길이 (성별, 국가코드 등 정형화된 짧은 코드에 적합)
* `varchar(n)`: 최대 길이 `n`자 내 가변 길이 (이름, 이메일 등 길이가 예측 가능한 일반 문자열에 적합)
* `text`: 길이 제한 없는 가변 길이 (게시글 본문, 리뷰 등 불규칙하고 긴 문자열에 적합)

### ③ 논리 / 날짜 / 시간
* `boolean`: `true` / `false` / `null`
* `date`: 날짜 (`YYYY-MM-DD`)
* `time`: 시간 (`HH:MI:SS`)
* `timestamp` / `timestamptz`: 날짜+시간 / 시간대(Timezone) 포함 날짜+시간

### ④ JSON & 기타
* `json`: 텍스트 형태 문자열 저장
* `jsonb`: 바이너리 포맷 파싱 저장 (인덱싱 및 빠른 검색 지원)
* `Enum`: 사전 정의된 고정 값 목록만 허용하는 열거형 타입

## 5. 스키마와 키(Key) 구조

### ① 스키마 (Schema)
* 데이터베이스의 테이블 구조, 컬럼 속성, 데이터 타입, 제약조건을 명세한 설계도

### ② 기본키 (Primary Key, PK)
* 테이블당 반드시 **하나**만 존재
* **고유성(Unique)**과 **최소성(NOT NULL)** 필수
* 여러 컬럼을 묶어 하나의 PK로 구성하는 방식을 **복합키(Composite Key)**라고 함

### ③ 외래키 (Foreign Key, FK)
* 다른 테이블의 기본키(PK)를 참조하여 관계를 형성하는 열
* 한 테이블에 여러 개 존재 가능

### ④ 참조 무결성과 삭제 옵션
참조 중인 부모 행의 삭제로 인해 고아 데이터(Orphan Data)가 발생하는 것을 차단합니다.
* **기본 동작**: 참조 중인 행 삭제 불가 (Restricted / No Action)
* `ON DELETE CASCADE`: 부모 행 삭제 시 이를 참조하는 외래키 행도 자동 삭제
* `ON DELETE SET NULL`: 부모 행 삭제 시 해당 외래키 값을 `NULL`로 변경

## 💡 오늘의 회고
* **실행 순서의 중요성**: 왜 SQL 쿼리 작성 시 `WHERE` 절에서 `SELECT`의 별칭을 사용할 수 없는지 명확히 이해했다.
* **데이터 모델링 관점**: 데이터 타입 선정(`VARCHAR` vs `TEXT`, `json` vs `jsonb`)과 참조 무결성 옵션(`CASCADE` 등)이 데이터베이스 안정성과 조회 성능에 결정적인 영향을 미친다는 것을 배웠다.

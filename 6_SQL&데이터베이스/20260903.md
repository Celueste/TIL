# 1. 핵심 개념

## 데이터베이스 정규화

정규화는 데이터베이스 설계 시 중복 데이터를 최소화하고 데이터의 일관성과 무결성을 유지하기 위해 테이블을 단계별로 분해하는 과정이다.

정규화를 진행하지 않으면 데이터 조작 시 다음과 같은 이상(Anomaly) 현상이 발생할 수 있다.

- 삽입 이상: 원하지 않는 불필요한 데이터를 함께 입력해야만 데이터 삽입이 가능한 현상이다.
- 갱신 이상: 중복된 데이터 중 일부만 수정되어 데이터 간의 불일치가 발생하는 현상이다.
- 삭제 이상: 특정 데이터를 삭제할 때 보존해야 할 다른 유용한 정보까지 함께 삭제되는 현상이다.

정규화는 보통 1단계부터 3단계까지 순차적으로 적용한다.

- 제1정규형 (1NF): 테이블의 모든 컬럼이 더 이상 쪼개질 수 없는 단 하나의 값(원자값)만을 가지도록 구성한다.
- 제2정규형 (2NF): 제1정규형을 만족하면서, 복합 기본키의 일부분에만 종속되는 부분 함수 종속을 제거하고 완전 함수 종속을 만족하도록 분리한다.
- 제3정규형 (3NF): 제2정규형을 만족하면서, 기본키가 아닌 일반 컬럼 간에 서로 종속되는 이행적 함수 종속(`A`가 `B`를 결정하고 `B`가 `C`를 결정하는 구조)을 제거한다.

반정규화는 지나친 정규화로 인해 테이블이 과도하게 쪼개져 조인(`JOIN`) 연산 비용이 커지는 문제를 해결하기 위해, 성능 향상을 목적으로 의도적으로 중복을 허용하는 설계 기법이다.

## SQL 명령어 4대 분류

SQL 문법은 역할과 목적에 따라 네 가지 범주로 분류한다.

- DDL (Data Definition Language, 데이터 정의어): 테이블이나 데이터베이스와 같은 데이터의 구조 자체를 생성, 수정, 삭제하는 명령어이다. (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`)
- DML (Data Manipulation Language, 데이터 조작어): 테이블 내부의 실제 행 데이터를 조회, 입력, 수정, 삭제하는 명령어이다. (`SELECT`, `INSERT`, `UPDATE`, `DELETE`)
- DCL (Data Control Language, 데이터 제어어): 데이터베이스 접근 및 작업 권한을 부여하거나 회수하는 명령어이다. (`GRANT`, `REVOKE`)
- TCL (Transaction Control Language, 트랜잭션 제어어): 작업 단위인 트랜잭션의 처리 결과를 최종적으로 확정하거나 취소하는 명령어이다. (`COMMIT`, `ROLLBACK`)

## 제약 조건과 자동증감 키

무결성을 보장하기 위해 컬럼에 다양한 제약 조건을 지정할 수 있다.

- `PRIMARY KEY`: 각 행을 유일하게 식별하는 기본키로, 중복 값과 `NULL`을 모두 허용하지 않는다.
- `NOT NULL`: 빈 값(`NULL`)이 입력되는 것을 허용하지 않는다.
- `UNIQUE`: 컬럼 내 중복 값을 허용하지 않으나 `NULL` 저장은 허용한다.
- `DEFAULT`: 데이터 입력 시 값을 따로 지정하지 않았을 때 기본으로 들어갈 값을 설정한다.
- `REFERENCES`: 다른 테이블의 기본키를 참조하는 외래키(FOREIGN KEY)를 설정하며, 부모 테이블에 존재하지 않는 값의 입력을 방지한다.

행 번호나 고유 식별자를 자동으로 1씩 증가시키며 생성하기 위해 자동증감 키를 사용한다.

- 표준 SQL: `INT GENERATED ALWAYS AS IDENTITY` 구문을 사용한다.
- PostgreSQL: 데이터 크기에 따라 `SERIAL`(4바이트 정수), `BIGSERIAL`(8바이트 큰 정수) 키워드를 지원한다.

# 2. 실습 및 코드

## 테이블 생성 (CREATE TABLE)

~~~sql
CREATE TABLE products (
    product_id   INT            PRIMARY KEY,
    product_name VARCHAR(100)   NOT NULL,
    price        DECIMAL(10, 2) NOT NULL,
    category     VARCHAR(50),
    created_at   DATE           NOT NULL
);
~~~

- `CREATE TABLE products`는 상품 정보를 저장할 `products` 테이블을 생성한다.
- `product_id`를 `INT` 타입으로 지정하고 고유 식별을 위해 `PRIMARY KEY` 제약 조건을 설정한다.
- `product_name`과 `category`는 가변 길이 문자열 타입인 `VARCHAR`를 적용한다.
- `price`는 전체 10자리 중 소수점 이하 2자리를 저장할 수 있는 `DECIMAL(10, 2)` 타입을 지정하고 빈 값을 방지하기 위해 `NOT NULL`을 부여한다.
- `created_at`은 날짜 정보를 저장하는 `DATE` 타입으로 선언한다.

## 데이터 일괄 삽입 (INSERT INTO)

~~~sql
INSERT INTO products (product_id, product_name, price, category, created_at)
VALUES
    (1, '노트북 파우치', 25000.00, '가방', '2024-01-10'),
    (2, '무선 마우스',   35000.00, '전자기기', '2024-01-15'),
    (3, '볼펜 세트',      8000.00, '문구', '2024-01-20');
~~~

- `INSERT INTO products (...)`에 데이터를 넣을 컬럼 목록을 직접 명시하여 데이터의 순서 불일치로 인한 오류를 방지한다.
- `VALUES` 뒤에 쉼표로 괄호를 구분하여 여러 행을 한 번에 추가하는 다중 행 삽입 방식을 사용한다.

## 테이블 확인 및 삭제

~~~text
\d products
~~~

- PostgreSQL 터미널(psql) 환경에서 `products` 테이블의 스키마 및 제약 조건 구조를 확인한다.

~~~sql
DROP TABLE products;
~~~

- `DROP TABLE`은 대상 테이블과 그 안에 포함된 모든 데이터를 데이터베이스에서 완전히 삭제한다.
- 실행 후 복구가 불가능하므로 주의해서 사용해야 한다.

# 3. 비교 정리

## 데이터 및 구조 삭제 명령어 비교

| 구분 | `DROP` | `TRUNCATE` | `DELETE` |
|---|---|---|---|
| 명령어 분류 | DDL | DDL | DML |
| 처리 대상 | 테이블 전체 (구조 + 데이터) | 테이블 내 모든 행 데이터 | 조건에 따른 행 데이터 |
| 테이블 구조 보존 | 완전히 삭제됨 | 유지됨 | 유지됨 |
| 처리 속도 | 즉각 처리 | 고속 초기화 | 행 단위 확인으로 상대적으로 느림 |
| 롤백(`ROLLBACK`) 여부 | 불가능 | DBMS 및 트랜잭션 설정에 따라 제한적 | 가능 |

## 종속성 관점의 정규화 비교

| 단계 | 제거 대상 종속성 | 설명 |
|---|---|---|
| 제2정규형 (2NF) | 부분 함수 종속 | 복합 기본키의 일부 컬럼에만 종속되는 관계를 분리한다. |
| 제3정규형 (3NF) | 이행적 함수 종속 | 기본키가 아닌 일반 컬럼이 다른 일반 컬럼을 결정하는 관계를 분리한다. |

# 4. 전체 흐름 정리

## 정규화 진행 순서

~~~text
원시 데이터 테이블
    |
    v
제1정규화 (1NF)
[모든 컬럼의 값을 원자값으로 변환]
    |
    v
제2정규화 (2NF)
[복합키의 부분 함수 종속 제거]
    |
    v
제3정규화 (3NF)
[일반 컬럼 간 이행적 종속 제거]
    |
    v
최종 정규화 테이블
~~~

# 5. 핵심 정리

## 핵심 코드

~~~sql
CREATE TABLE orders (
    order_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_name VARCHAR(50) NOT NULL
);
~~~

- 표준 SQL 방식으로 자동증감 식별자 컬럼을 정의하며 테이블을 생성한다.

~~~sql
COMMIT;
ROLLBACK;
~~~

- `COMMIT`은 지금까지의 작업을 데이터베이스에 영구 반영하고, `ROLLBACK`은 직전 커밋 상태로 취소하여 복구한다.

## 핵심 개념

- 정규화는 1NF(원자값 보장), 2NF(부분 함수 종속 제거), 3NF(이행적 함수 종속 제거) 순으로 적용하여 이상 현상을 방지한다.
- 조인 성능 저하를 방지하기 위해 정규화 수준과 반정규화 필요성을 함께 검토해야 한다.
- SQL은 DDL(구조 정의), DML(데이터 조작), DCL(권한 제어), TCL(트랜잭션 제어)로 구분된다.
- `DROP`은 테이블을 제거하고, `TRUNCATE`는 구조를 남긴 채 데이터를 고속으로 비우며, `DELETE`는 특정 조건에 맞추어 행을 삭제한다.
- 외래키 제약조건(`REFERENCES`)은 부모 테이블에 존재하지 않는 값이 자식 테이블에 들어오는 것을 방지하여 무결성을 유지한다.

# 6. 느낀 점

데이터베이스 설계 시 정규화를 거쳐 중복과 이상 현상을 줄이는 단계별 원칙과, 성능을 위해 의도적으로 중복을 고려하는 반정규화의 필요성을 함께 정리했다. 특히 2정규형의 부분 함수 종속과 3정규형의 이행적 종속의 구분 기준을 복합키 관점과 일반 컬럼 간의 관점으로 나누어 명확히 정립할 수 있었다. 또한 데이터를 삭제하는 명령어를 단순히 지우는 행위로 묶지 않고, 구조 삭제(`DROP`), 고속 초기화(`TRUNCATE`), 조건부 데이터 삭제(`DELETE`)로 나누어 동작 차이와 롤백 가능 여부를 구분하여 학습했다.

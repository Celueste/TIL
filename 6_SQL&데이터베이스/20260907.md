## 📝 오늘 배운 내용 요약

- `UNION`을 통한 세로 방향 행 결합과 `JOIN`(INNER, LEFT, RIGHT, FULL)을 통한 가로 방향 열 결합 방식을 익혔다.

# 1. 핵심 개념

## 데이터 조회 및 필터링

### SELECT와 FROM
- `SELECT`는 테이블에서 조회할 열(Column)을 지정한다.
- `FROM`은 데이터를 가져올 대상 테이블을 지정한다.
- `*` 기호는 테이블의 모든 열을 가져올 때 사용한다.
- 실무에서는 불필요한 데이터 조회를 줄이고 테이블 변경에 유연하게 대처하기 위해 필요한 열만 직접 지정하는 것이 안전하다.

### DISTINCT
- 컬럼 내 중복된 값을 제거하고 고유한(Unique) 값만 남길 때 사용한다.

### WHERE
- 조건식이 참(`TRUE`)인 행만 필터링하여 조회한다.

### 조건 연산자 종류
- 비교 연산자: `=`, `!=`, `>`, `<`, `>=`, `<=`
- 논리 연산자: `AND`(모두 만족), `OR`(하나 이상 만족)
- 목록 검색: `IN`(목록 중 일치), `NOT IN`(목록에 미포함)
- 범위 검색: `BETWEEN A AND B`(A 이상 B 이하 범위, 경계값 포함)
- 문자열 패턴 검색: `LIKE` (`%`는 임의의 문자열을 의미)
- NULL 비교: `IS NULL`(비어 있는 값 확인), `IS NOT NULL`(값이 있는 데이터 확인)
- `NULL`은 정의되지 않은 특수 상태이므로 `=` 연산자로 비교할 수 없다.

### CASE WHEN
- 조건에 따라 서로 다른 값을 반환하여 새로운 가상 열을 생성한다.
- 위에서부터 순차적으로 조건을 검사하며, 가장 먼저 참(`TRUE`)이 되는 조건의 결과를 적용하고 종료한다. 따라서 조건의 배치 순서가 중요하다.

## 데이터 집계와 그룹화

### 집계함수
- 여러 행의 값을 계산하여 하나의 결과값으로 요약한다.
- `COUNT`: 행 개수 계산
- `SUM`: 합계 계산
- `AVG`: 평균 계산
- `MIN`: 최솟값 확인
- `MAX`: 최댓값 확인
- `COUNT(*)`는 NULL 여부와 무관하게 전체 행 수를 세지만, `COUNT(열이름)`은 해당 열에서 NULL이 아닌 값만 센다.

### GROUP BY
- 특정 열의 고유값을 기준으로 데이터를 그룹화한 뒤 집계함수를 적용한다.
- `SELECT` 절에 집계함수 이외의 컬럼이 포함되어 있다면, 그 컬럼은 반드시 `GROUP BY` 절에 명시되어야 한다.

### WHERE와 HAVING
- `WHERE`는 `GROUP BY`가 실행되기 전 개별 행을 필터링한다.
- `HAVING`은 `GROUP BY`로 그룹화되고 집계함수가 계산된 결과를 필터링한다.

## 테이블 결합

### UNION과 UNION ALL
- 여러 `SELECT` 결과 집합을 세로(행) 방향으로 합친다.
- 조회하는 열의 개수가 동일해야 하며, 대응되는 열의 데이터 타입이 호환되어야 한다. 열 이름은 달라도 무방하며 최종 열 이름은 첫 번째 쿼리를 따른다.
- `UNION`은 합친 후 중복 행을 제거하고, `UNION ALL`은 중복을 포함한 모든 행을 유지한다.

### JOIN
- 두 개 이상의 테이블을 공통 키(Key) 컬럼 기준으로 가로(열) 방향으로 연결한다.
- `ON` 절을 사용하여 연결할 조건을 지정한다.
- 테이블 별칭(Alias)을 사용하면 긴 테이블 이름을 간결하게 표현할 수 있다.

### JOIN의 종류
- `INNER JOIN`: 양쪽 테이블 모두에 조건이 일치하는 행만 조회한다.
- `LEFT JOIN`: 왼쪽 테이블의 전체 행을 유지하고, 오른쪽 테이블에서 일치하는 데이터를 가져온다. 일치하는 값이 없으면 NULL로 채운다.
- `RIGHT JOIN`: 오른쪽 테이블의 전체 행을 유지하고 왼쪽 데이터를 연결한다.
- `FULL OUTER JOIN`: 양쪽 테이블의 모든 행을 포함하며, 일치하지 않는 반대쪽 데이터는 NULL로 표시한다.

# 2. 실습 및 코드

## 데이터 조회 및 중복 제거

~~~sql
SELECT DISTINCT store_id
FROM orders;
~~~

- `orders` 테이블에서 `store_id` 컬럼을 조회한다.
- `DISTINCT`를 사용하여 중복된 매장 ID를 하나씩만 표시한다.

## 조건 필터링 실습

~~~sql
SELECT *
FROM orders
WHERE store_id = 1;
~~~

- `orders` 테이블에서 모든 열(`*`)을 조회한다.
- `store_id`가 1인 행만 필터링하여 가져온다.

~~~sql
SELECT order_id, shipped_date
FROM orders
WHERE shipped_date IS NULL;
~~~

- 배송일자(`shipped_date`)가 아직 입력되지 않은 행을 조회한다.
- NULL 값 확인을 위해 `IS NULL` 연산자를 사용한다.

## CASE WHEN 조건 분기

~~~sql
SELECT order_id,
       list_price,
       CASE
           WHEN list_price < 100 THEN '저가'
           WHEN list_price < 500 THEN '중가'
           ELSE '고가'
       END AS price_grade
FROM order_items;
~~~

- `order_items` 테이블의 각 품목에 대해 가격대를 분류한다.
- `list_price`가 100 미만이면 '저가', 100 이상 500 미만이면 '중가', 그 외 500 이상은 '고가'로 처리하여 `price_grade`라는 열로 출력한다.

## 집계 및 그룹화

~~~sql
SELECT store_id,
       COUNT(*) AS order_cnt
FROM orders
WHERE order_status = 3
GROUP BY store_id
HAVING COUNT(*) > 100;
~~~

- `orders` 테이블에서 배송완료 상태(`order_status = 3`)인 주문만 먼저 필터링한다.
- 필터링된 행들을 `store_id` 기준으로 그룹화한다.
- 각 매장별 주문 건수(`COUNT(*)`)를 계산한 후, 건수가 100건을 넘는 매장만 결과로 출력한다.

## 세로 결합 (UNION)

~~~sql
SELECT store_id
FROM staffs

UNION

SELECT store_id
FROM orders;
~~~

- `staffs` 테이블의 `store_id`와 `orders` 테이블의 `store_id`를 하나의 결과 목록으로 합친다.
- `UNION`을 사용하여 양쪽 결과의 중복 행을 제거하고 고유값만 출력한다.

## 가로 결합 (INNER JOIN 및 LEFT JOIN)

~~~sql
SELECT o.order_id,
       c.first_name,
       c.last_name
FROM orders o
INNER JOIN customers c
    ON o.customer_id = c.customer_id;
~~~

- `orders` 테이블에 `o`, `customers` 테이블에 `c`라는 별칭을 부여한다.
- 두 테이블의 `customer_id` 값이 일치하는 행만 가로로 연결하여 주문 ID와 고객 이름을 조회한다.

~~~sql
SELECT c.customer_id,
       c.first_name,
       o.order_id
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id;
~~~

- `customers` 테이블의 모든 고객 정보를 유지한다.
- 주문 이력이 없는 고객의 경우 `order_id`에 NULL이 할당되어 출력된다.

# 3. 비교 정리

## 검색 연산자 비교

| 구분 | `IN` | `LIKE` |
|---|---|---|
| 목적 | 고정된 값 목록 일치 확인 | 특정 패턴 포함 여부 검색 |
| 비교 방식 | 완전 일치 | 부분 패턴 일치 (`%`, `_` 사용) |
| 예시 | `name IN ('전소현')` | `name LIKE '%전소현%'` |

## 필터링 조건문 비교

| 구분 | `WHERE` | `HAVING` |
|---|---|---|
| 필터링 시점 | `GROUP BY` 이전 | `GROUP BY` 이후 |
| 적용 대상 | 개별 원본 행 | 그룹화 집계 결과 |
| 집계함수 사용 | 불가 | 가능 |
| 예시 | `WHERE quantity > 0` | `HAVING SUM(quantity) > 100` |

## 집합 결합 비교

| 구분 | `UNION` | `JOIN` |
|---|---|---|
| 결합 방향 | 세로 (행 추가) | 가로 (열 추가) |
| 결합 기준 | 동일한 열 개수 및 데이터 타입 | 공통 키 컬럼 (`ON` 조건절) |
| 사용 목적 | 유사 구조의 데이터 통합 | 연관된 서로 다른 테이블의 정보 확장 |
| 예시 | 2023년 데이터 + 2024년 데이터 | 주문 내역 테이블 + 고객 상세 테이블 |

## 조인 방식 비교

| 조인 종류 | 포함되는 데이터 | 매칭되지 않는 데이터 처리 |
|---|---|---|
| `INNER JOIN` | 양쪽 모두 조건에 일치하는 데이터 | 결과에서 제외 |
| `LEFT JOIN` | 왼쪽 테이블 전체 및 오른쪽 일치 데이터 | 오른쪽 컬럼 NULL 처리 |
| `RIGHT JOIN` | 오른쪽 테이블 전체 및 왼쪽 일치 데이터 | 왼쪽 컬럼 NULL 처리 |
| `FULL OUTER JOIN` | 양쪽 테이블의 모든 데이터 | 반대쪽 컬럼 NULL 처리 |

# 4. 전체 흐름 정리

## SQL 쿼리 논리적 처리 순서

~~~text
FROM (대상 테이블 확인)
  |
  v
WHERE (개별 행 필터링)
  |
  v
GROUP BY (기준 컬럼별 그룹화)
  |
  v
HAVING (집계 결과 필터링)
  |
  v
SELECT (출력할 컬럼 선택 및 가공)
  |
  v
ORDER BY (최종 결과 정렬)
~~~

# 5. 핵심 정리

## 핵심 코드

~~~sql
SELECT store_id,
       COUNT(*) AS order_cnt
FROM orders
WHERE order_status = 3
GROUP BY store_id
HAVING COUNT(*) >= 50
ORDER BY order_cnt DESC;
~~~

- 상태 조건에 맞는 행만 먼저 필터링한 후 그룹화 및 집계를 수행하고, 집계 조건을 만족하는 결과만 정렬하여 조회한다.

~~~sql
SELECT o.order_id, c.customer_name
FROM orders o
LEFT JOIN customers c ON o.customer_id = c.customer_id;
~~~

- 공통 식별자를 기준으로 주문 정보에 고객 정보를 가로로 결합한다.

## 핵심 개념

- `SELECT`와 `FROM`은 조회의 출발점이며, `DISTINCT`로 중복을 배제할 수 있다.
- `NULL` 판별에는 `=` 대신 반드시 `IS NULL` 또는 `IS NOT NULL`을 사용해야 한다.
- `CASE WHEN`은 상단 조건부터 우선 적용되므로 범위 설계 순서가 핵심이다.
- `WHERE`는 그룹화 전 개별 데이터를 거르고, `HAVING`은 그룹화 후 요약 데이터를 거른다.
- `UNION`은 결과를 세로로 이어 붙이고, `JOIN`은 공통 키를 바탕으로 결과를 가로로 합친다.

# 6. 느낀 점

기본적인 데이터 조회 구문부터 그룹 집계와 다중 테이블 결합까지 SQL의 핵심 문법 흐름을 순차적으로 정리했다. 단순히 문법을 외우는 것보다 SQL 엔진이 데이터를 해석하는 논리적 실행 순서(`FROM` - `WHERE` - `GROUP BY` - `HAVING` - `SELECT` - `ORDER BY`)를 이해하는 것이 각 조건절의 용도를 구분하는 데 핵심이라는 점을 확인했다. 또한 테이블 결합 시 데이터의 누락 여부에 따라 적절한 JOIN 방식을 선택하는 기준을 명확히 익힐 수 있었다.

# 데이터베이스 개발 환경 구축

## 1. DBeaver

### DBeaver란?

DBeaver는 다양한 데이터베이스에 접속하여 데이터를 조회하고 관리할 수 있는 **데이터베이스 관리 도구(DBMS Client)**이다.

MySQL, PostgreSQL, SQLite 등 여러 데이터베이스에 연결할 수 있으며 SQL 작성, 테이블 조회 및 데이터 수정 등의 작업을 GUI 환경에서 수행할 수 있다. DBeaver는 SQL Editor, 데이터 편집, ER Diagram 등의 기능을 제공한다.

### 왜 설치하는가?

데이터베이스를 명령어만으로 관리하면 다음과 같은 작업이 불편할 수 있다.

* 데이터베이스 목록 확인
* 테이블 구조 확인
* SQL 작성 및 실행
* 데이터 조회
* 테이블 데이터 수정

DBeaver를 사용하면 이러한 작업을 화면에서 직관적으로 수행할 수 있다.

즉,

> **Docker에서 데이터베이스를 실행하고 → DBeaver에서 데이터베이스에 접속하여 관리한다.**

### 어디에 설치하는가?

DBeaver는 **Windows 컴퓨터에 일반 프로그램처럼 설치**한다.

예를 들어 다음과 같은 구조가 된다.

```text
Windows PC
│
├── Docker Desktop
│
├── DBeaver
│
└── 프로젝트 폴더
```

공식 다운로드 페이지에서 Windows용 설치 파일(EXE)을 다운로드하여 설치할 수 있다.

[DBeaver 공식 다운로드](https://dbeaver.io/download/?utm_source=chatgpt.com)

# 2. ERDCloud

### ERD란?

ERD(Entity Relationship Diagram)는 데이터베이스의 구조와 테이블 간 관계를 그림으로 표현한 것이다.

예를 들어 쇼핑몰 데이터베이스가 있다고 가정하면 다음과 같은 테이블이 있을 수 있다.

```text
USER
 ├── user_id
 ├── name
 └── email

ORDER
 ├── order_id
 ├── user_id
 └── order_date
```

이때 `USER`와 `ORDER` 테이블은 `user_id`를 통해 관계를 가질 수 있다.

ERD에서는 이러한 관계를 시각적으로 표현한다.

```text
USER
 │
 │ 1 : N
 │
ORDER
```

즉,

> 한 명의 사용자는 여러 개의 주문을 생성할 수 있다.

---

### ERDCloud를 사용하는 이유

ERDCloud는 데이터베이스 설계도를 웹에서 작성할 수 있는 도구이다.

데이터베이스를 실제로 만들기 전에 다음과 같은 내용을 미리 설계할 수 있다.

* 어떤 테이블이 필요한가?
* 각 테이블에는 어떤 컬럼이 필요한가?
* Primary Key는 무엇인가?
* Foreign Key는 무엇인가?
* 테이블끼리 어떤 관계를 가지는가?

예를 들어 실제 개발 과정은 다음과 같이 진행될 수 있다.

```text
1. 서비스 기획
        ↓
2. 필요한 데이터 분석
        ↓
3. ERD 작성
        ↓
4. 데이터베이스 생성
        ↓
5. 테이블 생성
        ↓
6. 애플리케이션 개발
```

### 어디에 설치하는가?

ERDCloud는 **웹 기반 서비스이므로 컴퓨터에 설치하지 않아도 된다.**

웹 브라우저에서 접속하여 사용한다.

```text
Chrome / Edge
      ↓
ERDCloud 접속
      ↓
ERD 작성
```

따라서 ERDCloud는 Docker나 Windows에 별도로 설치하는 프로그램이 아니다.

[ERDCloud](https://www.erdcloud.com/?utm_source=chatgpt.com)

# 3. Docker

### Docker란?

Docker는 애플리케이션이나 데이터베이스를 **컨테이너(Container)**라는 독립적인 환경에서 실행할 수 있도록 도와주는 플랫폼이다.

예를 들어 MySQL을 설치하려면 일반적으로 다음과 같은 과정이 필요하다.

```text
MySQL 다운로드
        ↓
설치
        ↓
환경 설정
        ↓
계정 설정
        ↓
포트 설정
```

Docker를 사용하면 컨테이너를 실행하는 방식으로 비교적 쉽게 데이터베이스 환경을 구성할 수 있다.

```text
Docker
   ↓
MySQL Container 실행
   ↓
MySQL 데이터베이스 사용
```

---

### 왜 Docker를 설치하는가?

개발을 하다 보면 여러 프로그램과 데이터베이스가 필요하다.

예를 들어,

```text
MySQL
Redis
MongoDB
PostgreSQL
```

각 프로그램을 Windows에 직접 설치하면 컴퓨터 환경이 복잡해질 수 있다.

Docker를 사용하면 각각을 독립된 컨테이너에서 실행할 수 있다.

```text
Windows
│
└── Docker Desktop
      │
      ├── MySQL Container
      │
      ├── Redis Container
      │
      └── PostgreSQL Container
```

따라서 Docker를 사용하면 다음과 같은 장점이 있다.

* 프로그램 설치 과정 단순화
* 개발 환경을 쉽게 재현 가능
* 여러 프로젝트의 환경을 분리 가능
* 사용하지 않는 컨테이너는 쉽게 삭제 가능
* 팀원과 동일한 개발 환경 구성 가능

---

### 어디에 설치하는가?

Docker Desktop은 **Windows에 설치**한다.

하지만 Windows 환경에서는 내부적으로 Linux 기반 환경을 사용하기 때문에 일반적으로 다음과 같은 구조로 동작한다.

```text
Windows
│
├── Docker Desktop
│
└── WSL
      │
      └── Linux 환경
            │
            └── Docker Container
                  │
                  └── MySQL
```

즉,

> **Docker Desktop은 Windows에 설치하고, 실제 컨테이너는 Docker가 관리하는 Linux 환경에서 실행된다.**

# 전체 구조

현재 사용하는 도구들의 역할은 다음과 같다.

```text
┌─────────────────────┐
│      ERDCloud       │
│                     │
│ 데이터베이스 설계      │
└──────────┬──────────┘
           │
           ▼
     테이블 구조 설계
           │
           ▼
┌─────────────────────┐
│       Docker        │
│                     │
│ MySQL 컨테이너 실행   │
└──────────┬──────────┘
           │
           ▼
      MySQL Database
           │
           ▼
┌─────────────────────┐
│       DBeaver       │
│                     │
│ DB 접속 및 관리       │
│ SQL 작성 및 실행      │
└─────────────────────┘
```

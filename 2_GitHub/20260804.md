# 1. 핵심 개념

### 버전 관리와 Git

버전 관리는 파일의 변경 이력을 시간 순서대로 기록하여 특정 시점으로 되돌리거나 변경 사항을 추적하는 작업이다.

Git은 로컬 환경에서 실행되는 분산 버전 관리 시스템(DVCS)이며, GitHub는 Git 저장소를 온라인에서 호스팅하고 협업을 지원하는 웹 서비스이다.

분산 버전 관리 환경에서는 중앙 서버뿐만 아니라 각 개발자의 컴퓨터에도 전체 이력이 저장되므로 네트워크 연결 없이도 로컬에서 커밋할 수 있다.

### Git의 3영역 구조

Git은 작업 파일의 라이프사이클을 세 단계 영역으로 나누어 관리한다.

- **Working Directory**: 실제 소스 코드를 편집하고 수정하는 로컬 작업 공간이다.
- **Staging Area**: 다음 커밋에 포함할 변경 파일들을 선별하여 등록하는 준비 공간이다.
- **Repository**: 커밋을 통해 프로젝트의 특정 시점 스냅샷 이력이 영구적으로 기록되는 공간이다.

### 브랜치와 HEAD

브랜치는 파일을 물리적으로 복사하는 것이 아니라 특정 커밋을 가리키는 이동 가능한 포인터이다.

`HEAD`는 현재 체크아웃되어 작업 중인 브랜치 또는 커밋을 가리키는 특수 포인터이다.

브랜치를 전환하면 `HEAD`가 대상 브랜치를 가리키며, 로컬 작업 공간의 파일 내용도 해당 커밋 시점의 상태로 전환된다.

# 2. 실습 및 코드

### 환경 설정 및 저장소 생성

Git 사용자 정보는 커밋 메타데이터에 기록되므로 최초 환경 설정이 필요하다.

~~~bash
# 사용자 정보 및 기본 에디터 설정
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global core.editor "code --wait"

# 전체 설정 확인
git config --list
~~~

설정 범위는 `local`(현재 저장소), `global`(사용자 계정), `system`(운영체제 전체)으로 나뉘며 범위가 좁을수록 우선순위가 높다.

새로운 저장소를 초기화하거나 원격 저장소를 복제할 때는 다음 명령어를 사용한다.

~~~bash
# 새로운 로컬 저장소 생성
git init

# 원격 저장소 복제 (전체 이력 포함)
git clone <repository-url>
~~~

### 기본 작업 흐름

파일을 수정한 후 스테이징 및 커밋을 수행하는 기본 흐름이다.

~~~bash
# 현재 작업 파일 상태 확인
git status

# 변경 파일 전체 스테이징
git add .

# 특정 파일 또는 변경 조각 단위 스테이징
git add README.md
git add -p filename.py

# 커밋 메시지와 함께 영구 스냅샷 기록
git commit -m "feat: add data preprocessing module"
~~~

### .gitignore 관리 및 추적 파일 제거

버전 관리에 포함하지 않을 환경 변수 파일이나 빌드 부산물은 `.gitignore`에 작성한다.

~~~text
.env
__pycache__/
*.pkl
*.h5
.ipynb_checkpoints/
*.log
build/
**/*.pyc
~~~

이미 원격 저장소나 인덱스에 등록되어 추적 중인 파일은 로컬 파일을 보존하면서 캐시만 삭제해야 한다.

~~~bash
# 로컬 파일은 유지하고 인덱스(추적 대상)에서만 제거
git rm --cached .env
git rm --cached -r __pycache__/
git commit -m "chore: remove tracked files that should be ignored"
~~~

API 키나 토큰이 이미 원격에 푸시된 경우에는 파일을 제외하는 것만으로 충분하지 않으므로 기존 키를 폐기하고 재발급해야 한다.

### 변경 사항 및 이력 확인

변경 내역과 과거 커밋 이력을 확인할 때 다음 명령어를 사용한다.

~~~bash
# 수정 사항 비교
git diff               # Working Directory와 Staging Area 비교
git diff --staged      # Staging Area와 마지막 커밋 비교
git diff HEAD          # Working Directory와 마지막 커밋 비교

# 요약 정보 및 파일 목록 확인
git diff --stat
git diff --name-only

# 커밋 이력 및 그래프 확인
git log --oneline
git log --oneline --graph --all --decorate

# 특정 커밋 상세 정보 확인
git show <SHA>
~~~

### 변경 취소 및 되돌리기

취소 작업의 범위와 원격 공유 여부에 따라 명령어를 구분하여 사용한다.

~~~bash
# 1. 작업 디렉토리의 수정 사항 취소
git restore filename.py

# 2. 스테이징 취소 (Working Directory 변경 사항 유지)
git restore --staged filename.py

# 3. 로컬 커밋 되돌리기 (원격 푸시 전 권장)
git reset --soft HEAD~1   # 커밋만 취소하고 스테이징 유지
git reset --mixed HEAD~1  # 커밋과 스테이징 취소, 작업 파일 유지
git reset --hard HEAD~1   # 커밋, 스테이징, 작업 파일 변경 전체 취소

# 4. 원격에 이미 푸시된 커밋 취소 (새로운 상쇄 커밋 생성)
git revert <SHA>
~~~

### 브랜치 생성 및 병합

독립적인 작업 공간을 분리하고 병합할 때 사용한다.

~~~bash
# 브랜치 생성 및 전환
git branch feature/login
git switch feature/login

# 생성과 전환을 동시에 수행
git switch -c feature/login

# 1. Fast-forward 가능 상태에서 강제 병합 커밋 생성
git merge --no-ff feature/login

# 2. 여러 커밋을 단일 변경으로 압축하여 병합
git merge --squash feature/login
git commit -m "feat: 로그인 기능 추가"
~~~

# 3. 비교 정리

### Git 환경 설정 우선순위

| 범위 | 옵션 | 적용 대상 | 우선순위 |
|---|---|---|---|
| local | `--local` | 현재 저장소 | 높음 (1순위) |
| global | `--global` | 현재 OS 사용자의 모든 저장소 | 중간 (2순위) |
| system | `--system` | 전체 OS 사용자와 모든 저장소 | 낮음 (3순위) |

### 되돌리기 명령어 비교

| 상황 | 추천 명령어 | 특징 |
|---|---|---|
| 커밋 전 파일 변경 취소 | `git restore <file>` | 작업 디렉토리의 변경 내용을 버림 |
| 스테이징 취소 | `git restore --staged <file>` | 작업 파일 내용은 유지하고 인덱스만 내림 |
| 로컬 커밋 되돌리기 | `git reset <commit>` | 과거 커밋으로 `HEAD` 이동 (원격 공유 전 사용) |
| 공유된 커밋 되돌리기 | `git revert <SHA>` | 기존 커밋을 보존하고 반대되는 새 커밋 생성 |

### 브랜치 병합 방식 비교

| 병합 방식 | 주요 동작 | 병합 커밋 생성 여부 |
|---|---|---|
| Fast-forward | 분기가 없을 때 대상 커밋으로 포인터만 전진 | 생성되지 않음 |
| 3-way merge | 공통 조상과 양 브랜치의 변경을 결합 | 생성됨 |
| `--no-ff` | 분기가 없어도 강제로 분기 이력을 보존 | 생성됨 |
| `--squash` | 작업 브랜치의 모든 커밋을 하나의 변경으로 압축 | 수동으로 직접 커밋 |

# 5. 핵심 정리

### 핵심 명령어

~~~bash
# 파일 변경 및 커밋 흐름
git status
git add <file>
git commit -m "커밋 메시지"

# 변경 취소 흐름
git restore <file>
git restore --staged <file>
git revert <SHA>

# 브랜치 전환 및 병합
git switch -c <branch-name>
git merge --no-ff <branch-name>
~~~

### 핵심 개념

- Git은 단순 파일 복사가 아니라 스냅샷 기반으로 상태를 저장한다.
- Staging Area를 활용하면 작업 중인 변경 사항 중 필요한 파일만 선별하여 단위 커밋을 구성할 수 있다.
- 브랜치는 특정 커밋을 가리키는 가벼운 포인터이며, `HEAD`는 현재 작업 중인 브랜치 위치를 나타낸다.
- 이미 원격에 푸시된 커밋 이력을 취소할 때는 이력을 덮어쓰는 `reset` 대신 `revert`를 사용해야 협업 충돌을 방지할 수 있다.

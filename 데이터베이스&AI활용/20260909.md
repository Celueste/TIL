# 1. 핵심 개념

## AI 서비스 데이터 모델 구조

AI 서비스에서는 모델 호출뿐만 아니라 입력값, 결과값, 메타데이터의 저장이 필수적이다. 질문, 문서, 응답, 피드백 데이터를 기록해야 서비스 성능 추적 및 장애 분석이 가능하다.

- `documents`: AI가 답변할 때 참조하는 문서 원본 데이터를 저장한다.
- `queries`: 사용자가 입력한 질문 정보를 기록한다.
- `query_logs`: AI 모델의 생성 답변, 사용 모델명, 성공 및 실패 상태, 에러 메시지를 기록한다.
- `feedbacks`: 모델 응답에 대해 사용자가 부여한 점수 및 평가 의견을 저장한다.

질문과 응답을 분리하는 이유는 하나의 질문에 대해 재시도나 다중 모델 호출이 발생할 수 있기 때문이다. 1:N 관계를 통해 하나의 질문에 복수의 응답 로그를 유연하게 연결할 수 있다.

## PostgreSQL 제약조건과 데이터베이스 기능

- `generated always as identity`: 기본키 ID를 데이터베이스가 자동으로 증가시키며 생성한다.
- `timestamptz`: 표준 시간대 정보를 포함하는 날짜 및 시간 타입이다.
- `now()`: 현재 시각을 반환하는 함수이며, 기본값(`default now()`)으로 주로 지정한다.
- `references`: 외래키(Foreign Key)를 설정하여 참조 무결성을 보장한다.
- `NOT NULL`: 컬럼에 빈 값이 입력되는 것을 방지한다.
- `CHECK`: 컬럼에 허용되는 값의 범위를 한정한다.
- `on delete cascade`: 부모 테이블의 행이 삭제될 때 이를 참조하는 자식 테이블의 행도 함께 삭제하여 고아 데이터 발생을 막는다.

## 트랜잭션 (Transaction)

트랜잭션은 여러 데이터베이스 작업을 하나의 작업 단위로 묶어 처리하는 개념이다.

- `COMMIT`: 트랜잭션 내의 모든 작업이 정상 처리되었을 때 최종 확정한다.
- `ROLLBACK`: 처리 도중 오류가 발생했을 때 이전 상태로 작업을 모두 되돌린다.

질문 데이터 저장과 응답 로그 저장이 분리되어 발생할 경우 생길 수 있는 데이터 불일치 문제를 방지한다.

## Supabase RPC (Remote Procedure Call)

데이터베이스 내부에 PostgreSQL 함수(PL/pgSQL)를 작성해 두고, 애플리케이션에서 이를 원격 호출하는 방식이다.

- 여러 테이블에 걸친 연속적인 데이터 삽입 작업을 하나의 함수로 제어할 수 있다.
- 네트워크 요청 횟수를 줄이고 트랜잭션 처리를 데이터베이스 내부에서 단일 실행할 수 있다.

## RLS (Row Level Security)

테이블의 특정 행(Row)에 접근할 수 있는 권한을 사용자별로 제어하는 보안 기능이다.

- `auth.uid()` 함수를 사용하여 현재 로그인한 사용자의 식별자를 판별한다.
- 접근 권한이 없는 행은 오류를 발생시키는 대신 조회 결과에서 제외된다.

# 2. 실습 및 코드

## Supabase 스키마 생성

외래키 참조 관계에 따라 부모 테이블부터 순차적으로 생성한다.

~~~sql
create table documents (
  id bigint generated always as identity primary key,
  user_id uuid references auth.users (id),
  title text not null,
  content text,
  status text default 'draft'
    check (status in ('draft', 'published', 'archived')),
  created_at timestamptz default now()
);
~~~

- `id`: 기본키로 지정되며 데이터베이스에서 자동 생성된다.
- `user_id`: Supabase 기본 인증 테이블인 `auth.users`의 ID를 참조한다.
- `title`: `not null` 조건을 걸어 필수 입력값으로 지정한다.
- `status`: `check` 제약조건을 통해 지정된 3가지 상태값만 입력할 수 있도록 제한한다.
- `created_at`: 데이터가 삽입될 때 `now()`를 통해 생성 시각을 기록한다.

외래키 연쇄 삭제(`on delete cascade`)를 적용할 때는 다음과 같이 작성한다.

~~~sql
document_id bigint
references documents(id)
on delete cascade
~~~

- 부모 테이블인 `documents`의 데이터가 삭제되면 연결된 하위 질문 데이터도 함께 삭제된다.

## Supabase RPC 함수 생성 및 호출

질문과 로그를 동시에 저장하는 PostgreSQL 함수를 정의한다.

~~~sql
create or replace function ask_and_log(
  p_user_id uuid,
  p_document_id bigint,
  p_question text,
  p_answer text,
  p_model_name text
)
returns bigint
language plpgsql
as $$
declare
  v_query_id bigint;
begin

  insert into queries (
    user_id,
    document_id,
    question,
    status
  )
  values (
    p_user_id,
    p_document_id,
    p_question,
    'completed'
  )
  returning id into v_query_id;

  insert into query_logs (
    query_id,
    answer,
    model_name,
    status
  )
  values (
    v_query_id,
    p_answer,
    p_model_name,
    'success'
  );

  return v_query_id;

end;
$$;
~~~

- `returning id into v_query_id`를 사용하여 생성된 질문 ID를 변수에 할당하고 다음 작업에서 활용한다.
- 두 단계의 삽입 작업이 단일 함수 단위로 실행된다.

Python SDK를 통해 정의한 RPC 함수를 실행한다.

~~~python
response = supabase.rpc("ask_and_log", {
    "p_user_id": user_id,
    "p_document_id": 1,
    "p_question": "useEffect는?",
    "p_answer": "렌더링 후 실행됩니다.",
    "p_model_name": "gpt-4o-mini",
}).execute()
~~~

- `supabase.rpc()` 메서드에 함수명과 매개변수 객체를 전달하여 호출한다.

## Supabase SDK 연동 및 데이터 저장

기본 클라이언트를 초기화하고 데이터를 조작한다.

~~~python
import os
from dotenv import load_dotenv
from supabase import create_client, Client

load_dotenv()

url = os.environ.get("SUPABASE_URL")
key = os.environ.get("SUPABASE_PUBLISHABLE_KEY")

supabase: Client = create_client(url, key)
~~~

- 환경 변수에서 프로젝트 URL과 API Key를 불러와 클라이언트를 생성한다.

질문 및 응답 로그 저장 함수를 구현한다.

~~~python
def create_query(user_id: str, document_id: int, question: str):
    response = (
        supabase.table("queries")
        .insert({
            "user_id": user_id,
            "document_id": document_id,
            "question": question,
        })
        .execute()
    )
    return response.data[0]

def save_query_log(query_id: int, answer: str, model_name: str):
    response = (
        supabase.table("query_logs")
        .insert({
            "query_id": query_id,
            "answer": answer,
            "model_name": model_name,
            "status": "success",
        })
        .execute()
    )
    return response.data[0]
~~~

- `created_at`이나 기본 `status`는 데이터베이스의 기본값이 자동으로 적용되므로 필수 필드만 전송한다.

## 문서 CRUD 함수 구현

~~~python
def create_document(user_id, title, content):
    return (
        supabase.table("documents")
        .insert({
            "user_id": user_id,
            "title": title,
            "content": content
        })
        .execute()
        .data[0]
    )

def get_documents(user_id):
    return (
        supabase.table("documents")
        .select("*")
        .eq("user_id", user_id)
        .order("created_at", desc=True)
        .execute()
        .data
    )

def update_document(document_id, new_title):
    return (
        supabase.table("documents")
        .update({"title": new_title})
        .eq("id", document_id)
        .execute()
        .data
    )

def delete_document(document_id):
    return (
        supabase.table("documents")
        .delete()
        .eq("id", document_id)
        .execute()
        .data
    )
~~~

- `update()`와 `delete()` 사용 시에는 반드시 `.eq()` 조건을 명시하여 의도치 않은 전체 데이터 수정을 방지해야 한다.

## RLS 정책 설정

~~~sql
alter table documents enable row level security;

create policy "Users can view own documents"
on documents
for select
using (auth.uid() = user_id);
~~~

- `alter table ... enable row level security`로 보안을 활성화한다.
- `auth.uid() = user_id` 조건을 통해 자신의 데이터만 조회할 수 있도록 제한한다.

## JOIN을 이용한 다중 테이블 조회

~~~sql
select
  d.title,
  q.question,
  l.answer,
  f.score
from documents d
join queries q on q.document_id = d.id
join query_logs l on l.query_id = q.id
left join feedbacks f on f.query_log_id = l.id
order by d.id;
~~~

- `join`을 통해 문서, 질문, 모델 응답 로그를 결합한다.
- 아직 피드백이 등록되지 않은 응답도 함께 확인하기 위해 `left join`을 사용한다.

## 데이터 품질 점검 쿼리

결측치 점검:

~~~sql
select id, user_id, title
from documents
where title is null or title = '';
~~~

- 제목 컬럼의 누락 여부를 확인한다.

중복 데이터 점검:

~~~sql
select user_id, title, count(*) as cnt
from documents
group by user_id, title
having count(*) > 1;
~~~

- 동일 사용자가 작성한 동일 제목 문서의 중복 여부를 그룹화하여 점검한다.

# 3. 비교 정리

## 데이터베이스 언어 구분

| 구분 | 정의 | 주요 명령어 |
|---|---|---|
| DDL | 데이터베이스 구조를 정의하고 변경하는 언어 | `CREATE`, `ALTER`, `DROP` |
| DML | 데이터를 조작하고 조회하는 언어 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| TCL | 트랜잭션을 관리하고 제어하는 언어 | `COMMIT`, `ROLLBACK` |

## CRUD 연산과 SDK 매핑

| CRUD | 역할 | SQL 명령어 | Supabase SDK 메서드 |
|---|---|---|---|
| Create | 데이터 생성 | `INSERT` | `.insert()` |
| Read | 데이터 조회 | `SELECT` | `.select()` |
| Update | 데이터 수정 | `UPDATE` | `.update()` |
| Delete | 데이터 삭제 | `DELETE` | `.delete()` |

## 테이블 역할 및 주요 컬럼

| 테이블명 | 역할 | 주요 컬럼 |
|---|---|---|
| `documents` | 참조용 문서 관리 | `id`, `user_id`, `title`, `content`, `status`, `created_at` |
| `queries` | 사용자 질문 관리 | `id`, `user_id`, `document_id`, `question`, `status`, `created_at` |
| `query_logs` | 모델 응답 및 상태 로그 | `id`, `query_id`, `answer`, `model_name`, `status`, `error_message`, `created_at` |
| `feedbacks` | 사용자 만족도 평가 | `id`, `query_log_id`, `score`, `comment`, `created_at` |

## 핵심 개념

- AI 서비스 백엔드는 단순 호출을 넘어 메타데이터와 실패 로그를 영구 보관하는 데이터베이스 구조가 필수적이다.
- 외래키 제약조건과 `on delete cascade`를 활용하면 관계의 일관성을 유지하고 고아 데이터를 차단할 수 있다.
- 다단계 데이터 처리는 트랜잭션 및 Supabase RPC를 적용하여 처리의 원자성을 보장해야 한다.
- RLS를 활성화하고 `auth.uid()` 조건을 설정하여 애플리케이션 레벨 이전 단계에서 데이터 접근 보안을 강화한다.
- 축적된 질의응답 로그와 피드백 데이터는 추후 RAG 시스템 고도화 및 LLMOps 성능 분석의 기반이 된다.

## 1. 코루틴과 비동기 처리

### 코루틴(Coroutine)의 개념

코루틴은 실행 도중에 잠시 멈추고 제어권을 다른 작업에 넘겼다가, 대기가 끝나면 멈췄던 지점부터 다시 실행을 이어갈 수 있는 함수이다. 

카페에서 커피가 완성될 때까지 직원이 멍하니 서서 기다리는 대신, 다음 손님의 주문을 접수하고 음료가 완성되면 다시 이전 작업을 이어받아 전달하는 방식과 유사하다.

~~~text
주문 접수
    ↓
커피 제조 요청
    ↓
기다리는 동안 다른 주문 처리
    ↓
커피 완성
    ↓
다시 해당 작업 처리
~~~

- 일반 함수는 한 번 호출되면 종료될 때까지 제어권을 독점한다.
- 코루틴은 I/O 작업 등으로 대기가 발생하는 순간 다른 작업에 제어권을 양보할 수 있다.

### 동기 처리와 비동기 처리

- **동기(Synchronous) 처리**: 작업들을 순서대로 하나씩 처리한다. 이전 작업의 대기 시간이 끝나야 다음 작업이 시작된다.
- **비동기(Asynchronous) 처리**: 하나의 작업이 대기하는 동안 다른 작업을 진행한다.

~~~text
[동기 처리]
철수 주문(접수) → 3초 대기 → 철수 커피 완성 → 영희 주문(접수) → 1초 대기 → 영희 커피 완성
총 소요 시간: 약 4초

[비동기 처리]
철수 주문 ─────── 3초 ─────── 완료
       ↘
        영희 주문 ─ 1초 ─ 완료
총 소요 시간: 약 3초
~~~

- 비동기 처리는 CPU 연산을 여러 개 동시에 돌리는 병렬 연산이라기보다, I/O 대기 시간 동안 낭비되는 CPU 자원을 다른 작업에 배정하는 효율적인 스케줄링 방식이다.

## 2. async와 await

### async def

비동기 방식으로 실행할 수 있는 코루틴 함수를 정의할 때 사용하는 키워드이다.

~~~python
async def brew_coffee(customer_name, wait_seconds):
    print(f"{customer_name}의 커피를 만들기 시작합니다.")
~~~

- `async def`로 정의된 함수는 일반 함수처럼 바로 실행되지 않고 호출 시 코루틴 객체를 반환한다.

### await

코루틴 내부에서 비동기 작업의 완료를 대기할 때 사용하는 키워드이다.

~~~python
# 비동기 코드에서 사용하는 논블로킹 대기
await asyncio.sleep(3)
~~~

- `await` 뒤에는 코루틴이나 비동기 작업 객체가 올 수 있다.
- `await`를 만나는 순간 해당 작업이 완료될 때까지 제어권을 이벤트 루프에 양보하며, 프로그램 전체가 멈추지 않는다.
- 일반적인 `time.sleep()`은 프로그램 전체를 멈추게(블로킹) 하므로 비동기 환경에서는 반드시 `await asyncio.sleep()`을 사용한다.

### asyncio.gather()

여러 개의 코루틴을 동시에 실행하고 그 결과들을 하나의 리스트로 취합할 때 사용한다.

~~~python
results = await asyncio.gather(
    brew_coffee("철수", 3),
    brew_coffee("영희", 1)
)
~~~

- 철수의 작업(3초)과 영희의 작업(1초)을 동시에 실행 요청한다.
- 작업 완료 순서(영희 → 철수)와 무관하게 `gather()`에 전달된 인자의 순서대로 결과 리스트가 정렬되어 반환된다.

## 3. 이벤트 루프와 실행 환경

### 이벤트 루프(Event Loop)

비동기 프로그래밍의 핵심 관리자이다. 등록된 코루틴 작업들을 감시하며, 대기 중인 작업은 대기 상태로 두고 즉시 실행할 수 있는 다른 작업을 찾아 CPU 제어권을 넘겨주는 스케줄링을 반복한다.

~~~text
작업 확인
  ↓
기다려야 하는 작업은 잠시 대기
  ↓
실행할 수 있는 다른 작업 처리
  ↓
완료된 작업 확인
  ↓
다음 작업 처리
~~~

### 실행 환경에 따른 차이

- **Jupyter Notebook (`.ipynb`)**: 환경 내부에서 이미 이벤트 루프가 상시 실행 중이다. 따라서 새로운 이벤트 루프를 생성하지 않고 셀에서 직접 `await`를 호출한다.
- **일반 Python 스크립트 (`.py`)**: 이벤트 루프가 기본으로 실행되어 있지 않으므로 `asyncio.run()`을 호출하여 이벤트 루프를 새로 생성하고 메인 코루틴을 실행해야 한다.

| 실행 환경 | 실행 문법 |
|---|---|
| Jupyter Notebook (`.ipynb`) | `await main()` |
| 일반 Python (`.py`) | `asyncio.run(main())` |

## 4. 실습 및 코드

### 비동기 카페 주문 처리 실습

두 손님의 주문을 비동기로 접수하여 대기 시간을 절약하는 전체 실습 코드이다.

~~~python
import asyncio
import time


async def brew_coffee(customer_name, wait_seconds):
    print(f"[{customer_name}] 커피 주문을 접수했습니다.")
    await asyncio.sleep(wait_seconds)
    print(f"[{customer_name}] {wait_seconds}초가 지나 커피가 준비되었습니다!")
    return f"{customer_name}의 아메리카노"


async def main():
    print("--- 비동기 카페가 문을 열었습니다! ---")
    start_time = time.time()

    results = await asyncio.gather(
        brew_coffee("철수", 3),
        brew_coffee("영희", 1)
    )

    end_time = time.time()
    print("--- 오늘 완성된 음료 명단 ---")
    print(results)
    print(f"총 소요 시간: {end_time - start_time:.2f}초")
~~~

- `brew_coffee`는 커피를 만드는 비동기 코루틴이다.
- `main` 함수 내부에서 `asyncio.gather`를 통해 철수와 영희의 주문을 동시에 실행한다.
- 철수의 주문이 3초 동안 대기하는 사이에 영희의 커피(1초) 제조가 완료된다.
- 전체 소요 시간은 동기 방식(4초)이 아닌 비동기 방식 기준 가장 긴 대기 시간인 약 3초가 소요된다.

### 실행 코드

- Jupyter Notebook 환경:
~~~python
await main()
~~~

- 일반 `.py` 파일 환경:
~~~python
if __name__ == "__main__":
    asyncio.run(main())
~~~

## 5. 비동기 HTTP 통신

네트워크 통신은 대표적인 I/O 대기 작업이므로 비동기 프로그래밍이 매우 유용하게 활용된다. `httpx` 라이브러리를 통해 동기와 비동기 통신을 구분하여 사용할 수 있다.

### httpx.Client (동기)

~~~python
import httpx

with httpx.Client() as client:
    response = client.get("https://example.com")
~~~

- 응답이 올 때까지 전체 스레드가 멈춘 상태로 대기한다.

### httpx.AsyncClient (비동기)

~~~python
import httpx

async with httpx.AsyncClient() as client:
    response = await client.get("https://example.com")
~~~

- `async with` 구문으로 비동기 컨텍스트 매니저를 생성한다.
- `await client.get()`을 사용하여 서버로부터 응답을 기다리는 동안 이벤트 루프가 다른 작업을 처리할 수 있다.

### HTTP 메서드 및 응답 확인

| 메서드 | 목적 | 사용 문법 |
|---|---|---|
| `GET` | 데이터 조회 | `await client.get(url)` |
| `POST` | 데이터 생성 | `await client.post(url)` |
| `PUT` | 데이터 전체 수정 | `await client.put(url)` |
| `PATCH` | 데이터 일부 수정 | `await client.patch(url)` |
| `DELETE` | 데이터 삭제 | `await client.delete(url)` |

응답 객체(`Response`)의 주요 속성과 메서드는 다음과 같다.

~~~python
response = await client.get(url)

print(response.status_code)
print(response.text)
print(response.json())
~~~

| 속성 및 메서드 | 역할 |
|---|---|
| `.status_code` | HTTP 상태 코드 확인 (200, 404 등) |
| `.text` | 본문 응답을 문자열로 반환 |
| `.content` | 본문 응답을 바이너리(바이트)로 반환 |
| `.json()` | JSON 포맷 응답을 Python 객체(딕셔너리/리스트)로 변환 |
| `.raise_for_status()` | 오류 상태 코드 수신 시 예외 발생 |

## 6. 오류와 해결

### 1) Jupyter Notebook에서 asyncio.run() 실행 오류

#### 오류 내용
~~~text
RuntimeError: asyncio.run() cannot be called from a running event loop
~~~

#### 오류 원인
주피터 노트북은 이미 자체적으로 백그라운드에서 이벤트 루프를 구동하고 있다. 실행 중인 이벤트 루프 내부에서 또다시 새 이벤트 루프를 생성하는 `asyncio.run()`을 호출하면 충돌이 발생한다.

#### 수정 코드
~~~python
# 잘못된 실행 (Jupyter)
# asyncio.run(main())

# 올바른 실행 (Jupyter)
await main()
~~~

#### 해결 방법
주피터 노트북 환경에서는 `asyncio.run()` 대신 최상위 레벨에서 직접 `await main()`을 호출한다.

#### 기억할 점
실행 환경이 주피터(`.ipynb`)인지 일반 파이썬 스크립트(`.py`)인지 확인하고 호출 방식을 분기해야 한다.

### 2) 비동기 코루틴 내부에서 time.sleep() 사용

#### 오류 내용
프로그램 실행 중 비동기로 등록된 다른 작업들이 대기 시간 동안 실행되지 못하고 순차적으로 지연된다.

#### 오류 원인
`time.sleep()`은 현재 스레드 자체를 블로킹하여 CPU를 멈추게 하므로, 이벤트 루프가 제어권을 다른 코루틴에 넘겨줄 기회를 차단한다.

#### 수정 코드
~~~python
# 잘못된 코드
# async def task():
#     time.sleep(3)

# 올바른 코드
async def task():
    await asyncio.sleep(3)
~~~

#### 해결 방법
비동기 함수 내부에서 지연 시간을 부여할 때는 반드시 비동기 전용 대기 함수인 `await asyncio.sleep()`을 사용한다.

#### 기억할 점
코루틴 안에서는 동기 블로킹 라이브러리 함수 호출을 피하고 논블로킹(Non-blocking) 함수를 사용해야 한다.

## 7. 비교 정리

### 동기 처리 vs 비동기 처리

| 비교 항목 | 동기 처리 | 비동기 처리 |
|---|---|---|
| 작업 방식 | 순차적으로 하나씩 처리 | 대기 시간 동안 다른 작업 수행 |
| 대기 시간 영향 | 다음 작업이 무조건 대기함 | 대기 시간 중 다른 코루틴 실행 가능 |
| 대표 대기 함수 | `time.sleep()` | `await asyncio.sleep()` |
| 함수 정의 | `def` | `async def` |
| 함수 실행 방식 | 일반 함수 호출 | `await` 또는 `asyncio.run()` |
| 병렬 작업 관리 | 순차 루프 실행 | `asyncio.gather()` 등으로 일괄 실행 |

### 일반 함수 vs 코루틴

| 구분 | 일반 함수 | 코루틴 |
|---|---|---|
| 선언 키워드 | `def` | `async def` |
| 반환 객체 | 함수의 반환값 | 코루틴 객체 |
| 대기 중 동작 | 호출 스레드를 블로킹할 수 있음 | 제어권을 이벤트 루프에 양보 가능 |
| 주 활용 분야 | 일반 CPU 연산 및 데이터 처리 | 네트워크 요청, 파일 입출력 등 I/O 대기 작업 |

### time.sleep() vs asyncio.sleep()

| 구분 | `time.sleep()` | `asyncio.sleep()` |
|---|---|---|
| 동작 방식 | 동기 블로킹 | 비동기 논블로킹 |
| 제어권 양보 여부 | 양보하지 않고 전체 흐름 차단 | 제어권을 이벤트 루프에 양보 |
| 사용 위치 | 일반 동기 스크립트 | `async def` 코루틴 내부 (`await` 필수) |

## 8. 전체 흐름 정리

~~~text
비동기 프로그램의 실행 흐름
       │
       ├─ 1. async def로 코루틴 선언
       │
       ├─ 2. I/O 작업 지점에 await 키워드 배치
       │
       ├─ 3. 이벤트 루프 구동
       │      ├─ Jupyter Notebook: await main()
       │      └─ 일반 .py 스크립트: asyncio.run(main())
       │
       ├─ 4. asyncio.gather()로 복수 코루틴 스케줄링
       │
       ├─ 5. await 대기 발생 시 제어권 양보 및 다음 코루틴 처리
       │
       └─ 6. 모든 작업 완료 후 결과 취합 및 반환
~~~

~~~text
비동기 작업 스케줄링 흐름
작업 A 시작 ────── (await 대기 발생) ─────────── 작업 A 재개 및 완료
                      │ (제어권 양보)
                      ↓
               작업 B 시작 ── (완료)
~~~

## 9. 핵심 정리

### 핵심 코드

~~~python
import asyncio


# 코루틴 정의
async def fetch_data():
    await asyncio.sleep(1)
    return "완료"


# 복수 작업 일괄 실행
async def main():
    results = await asyncio.gather(fetch_data(), fetch_data())
    print(results)


# 실행 (스크립트 환경)
asyncio.run(main())
~~~

### 핵심 개념

- 코루틴은 `async def`로 생성하고 내부에서 `await`를 통해 이벤트 루프에 제어권을 양보한다.
- `asyncio.gather()`는 여러 비동기 함수를 묶어 동시에 실행하고 결과를 순서대로 반환한다.
- 코루틴 안에서 `time.sleep()`을 쓰면 이벤트 루프 전체가 멈추므로 `await asyncio.sleep()`을 사용해야 한다.
- 실행 환경에 따라 주피터는 `await`, 일반 파이썬 파일은 `asyncio.run()`을 사용한다.

## 10. 느낀 점

이번 학습을 통해 비동기 프로그래밍은 단순히 작업을 병렬로 여러 개 돌리는 개념이 아니라, 대기 시간이 발생하는 순간 다른 작업을 처리할 수 있도록 제어권을 넘겨주는 효율적인 스케줄링 방식이라는 점을 명확히 정리했다. 특히 카페 주문 예시를 통해 `async def`, `await`, `asyncio.gather()`의 상관관계를 직관적으로 이해할 수 있었다. 
또한 주피터 노트북과 일반 `.py` 파일의 이벤트 루프 동작 차이로 인한 실행 방법 구분을 정리하여 실무 환경에서의 오류 발생 요인을 짚을 수 있었다. 앞으로 외부 API 통신이나 대용량 I/O 처리가 필요한 프로그램을 다룰 때 비동기 방식을 적재적소에 활용해야겠다고 생각했다.

# 1. 핵심 개념

## AI 서비스와 데이터베이스

AI 모델 자체는 사용자 정보나 대화 내역을 영구적으로 보존하지 않는다.

서비스를 지속적으로 운영하려면 사용자 정보, 업로드 문서, 질문 및 응답 기록을 별도의 저장소에 보존해야 한다.

데이터베이스는 데이터를 안전하게 저장하고 필요한 시점에 즉각 조회할 수 있도록 돕는다.

~~~text
사용자 요청
    |
    v
애플리케이션
    |
    v
DB에 데이터 저장 및 조회
    |
    v
필요한 데이터를 AI에 전달
    |
    v
AI 응답 반환
~~~

## PostgreSQL과 Supabase

PostgreSQL은 오픈소스 관계형 데이터베이스 관리 시스템(RDBMS)이다.

데이터를 테이블 형태로 관리하며, 엄격한 제약조건과 관계 설정을 통해 데이터의 일관성을 유지한다.

Supabase는 PostgreSQL을 기반으로 인증, API, 스토리지 기능을 통합 제공하는 BaaS 플랫폼이다.

~~~text
Supabase
├── PostgreSQL (데이터베이스 엔진)
├── Authentication (인증)
├── API (자동 생성 API)
└── Storage (파일 저장소)
~~~

## 클라이언트 - 서버 - DB 구조

웹 및 AI 서비스는 일반적으로 3계층 아키텍처로 동작한다.

| 구성 요소 | 역할 |
|---|---|
| Client | 사용자 입력을 받고 결과를 화면에 표시 |
| Server / API | 비즈니스 로직을 처리하고 데이터 접근 규칙 제어 |
| Database | 실제 영구 데이터를 저장 및 조회 |

- API는 프로그램 간에 정해진 규격으로 데이터를 주고받는 인터페이스이다.
- SDK는 이러한 API를 특정 언어 환경에서 쉽게 호출할 수 있도록 묶어둔 개발 도구 모음이다.

## 데이터베이스 개발 환경

Supabase 대시보드는 여러 기능을 지원한다.

| 메뉴 | 역할 |
|---|---|
| Table Editor | GUI 환경에서 테이블과 데이터를 직관적으로 확인 및 수정 |
| SQL Editor | SQL 문을 직접 작성하고 실행하여 스크립트 기반 작업 수행 |
| Database | 데이터베이스 스키마, 확장 기능 및 백업 관리 |
| Authentication | 사용자 계정 및 권한 관리 |
| Project Settings | 접속 URL, API Key 등 프로젝트 전반 설정 |

GUI 기반의 Table Editor는 직관적인 확인에 적합하며, 구조 변경의 재현성과 이력 관리가 필요한 작업에는 SQL Editor를 사용한다.

연결 정보는 `.env` 파일 등 환경 변수로 분리하여 관리해야 한다.

~~~text
SUPABASE_URL="https://your-project.supabase.co"
SUPABASE_PUBLISHABLE_KEY="your-key"
~~~

`service_role key`는 관리자 권한을 가지므로 클라이언트 코드나 공개 저장소에 절대로 노출하지 않는다.

## 제약조건과 데이터 무결성

데이터 무결성은 데이터가 정확하고 일관되며 신뢰할 수 있는 상태를 뜻한다.

데이터베이스는 테이블 컬럼에 제약조건을 설정하여 잘못된 데이터 유입을 사전에 방지한다.

| 제약조건 | 역할 |
|---|---|
| `PRIMARY KEY` | 각 행을 고유하게 식별 (NOT NULL + UNIQUE 결합) |
| `NOT NULL` | 컬럼에 비어 있는 값(NULL) 입력 방지 |
| `UNIQUE` | 테이블 내 중복 데이터 입력 방지 |
| `CHECK` | 특정 논리 조건에 부합하는 데이터만 허용 |
| `DEFAULT` | 값이 명시되지 않았을 때 기본값 자동 지정 |
| `FOREIGN KEY` | 다른 테이블의 기본키를 참조하여 참조 무결성 보장 |

## FOREIGN KEY와 테이블 관계

외래키(FOREIGN KEY)는 다른 테이블의 기본키를 참조하여 두 테이블 사이의 관계를 형성한다.

존재하지 않는 부모 레코드의 ID가 자식 테이블에 들어가는 것을 방지한다.

부모 데이터가 삭제될 때 자식 데이터를 처리하는 옵션은 다음과 같다.

| 옵션 | 동작 방식 |
|---|---|
| `RESTRICT` | 자식 테이블에 참조 데이터가 남아 있으면 부모 데이터 삭제 차단 |
| `CASCADE` | 부모 데이터 삭제 시 연관된 자식 데이터도 연쇄 삭제 |
| `SET NULL` | 부모 데이터 삭제 시 자식 테이블의 외래키 컬럼을 NULL로 변경 |

## TCL과 트랜잭션

TCL(Transaction Control Language)은 여러 데이터 변경 작업을 하나의 논리적 단위(트랜잭션)로 묶어 관리하는 언어이다.

작업 도중 오류가 발생하면 모든 작업을 취소하고, 전부 정상 완료되었을 때만 실제 데이터베이스에 반영하여 정합성을 지킨다.

| 명령어 | 역할 |
|---|---|
| `BEGIN` | 트랜잭션 작업 시작 선언 |
| `COMMIT` | 트랜잭션 내 모든 변경사항을 영구 반영 |
| `ROLLBACK` | 트랜잭션 내 모든 변경사항을 취소하고 시작 전으로 복구 |

# 2. 실습 및 코드

## DDL을 이용한 테이블 생성 및 변경

### 테이블 생성 (`CREATE TABLE`)

기본 사용자 테이블을 정의한다.

~~~sql
CREATE TABLE users (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email text UNIQUE NOT NULL,
    name text NOT NULL,
    created_at timestamptz DEFAULT now()
);
~~~

- `id` 컬럼은 자동 증가하는 정수형 고유 식별자이자 기본키로 선언한다.
- `email`은 공백일 수 없고 중복 값을 허용하지 않는다.
- `created_at`은 값을 지정하지 않으면 현재 시각(`now()`)이 기본 적용된다.

### 테이블 구조 변경 (`ALTER TABLE`)

기존 데이터를 유지한 상태로 구조를 수정한다.

~~~sql
ALTER TABLE documents
ADD COLUMN status text DEFAULT 'draft';

ALTER TABLE documents
RENAME COLUMN content TO body;
~~~

- `ADD COLUMN`을 통해 기본값이 `'draft'`인 `status` 컬럼을 새로 추가한다.
- `RENAME COLUMN`을 통해 기존 컬럼의 명칭을 `content`에서 `body`로 변경한다.

### 제약조건 적용 예시

컬럼 수준에서 `CHECK` 제약조건을 설정하여 유효한 값의 범위를 제한한다.

~~~sql
ALTER TABLE documents
ADD CONSTRAINT check_status
CHECK (status IN ('draft', 'published', 'archived'));
~~~

- `status` 컬럼에는 정의된 3가지 문자열 외의 다른 값이 들어올 수 없다.

### 테이블 삭제 (`DROP TABLE`)

~~~sql
DROP TABLE test_table;
~~~

- `DROP TABLE`은 테이블 스키마와 내부 데이터를 물리적으로 영구 삭제하므로 주의해야 한다.

## DML을 이용한 데이터 조작

### 단일 및 다중 행 추가 (`INSERT`)

~~~sql
INSERT INTO users (email, name)
VALUES ('minji@example.com', '김민지');

INSERT INTO users (email, name)
VALUES
    ('junho@example.com', '이준호'),
    ('sora@example.com', '박소라');
~~~

- 자동 증가 컬럼(`id`)이나 기본값이 지정된 컬럼(`created_at`)은 컬럼 목록에서 생략할 수 있다.

### 데이터 검증과 수정 (`UPDATE`)

데이터를 변경하기 전에는 반드시 동일한 조건문으로 대상 행을 먼저 검증해야 한다.

~~~sql
-- 1단계: 변경 대상 데이터 확인
SELECT id, title, status
FROM documents
WHERE id = 1;

-- 2단계: 데이터 수정
UPDATE documents
SET status = 'published',
    updated_at = now()
WHERE id = 1;

-- 3단계: 변경 결과 확인
SELECT id, title, status, updated_at
FROM documents
WHERE id = 1;
~~~

- `WHERE` 절을 누락하면 테이블 내의 모든 행이 일괄 수정되는 사고가 발생한다.

### 논리 삭제 처리

서비스 내 복구 기능이나 이력 보존을 위해 실제 행을 지우지 않고 상태 컬럼만 갱신한다.

~~~sql
-- 데이터 삭제 플래그 갱신
UPDATE documents
SET is_deleted = true,
    updated_at = now()
WHERE id = 1;

-- 삭제되지 않은 정상 데이터만 조회
SELECT id, title
FROM documents
WHERE is_deleted = false;
~~~

- `is_deleted` 컬럼을 조건절에 포함하여 활성 데이터만 필터링한다.

## TCL을 이용한 트랜잭션 제어

### 정상 커밋 흐름

사용자 생성과 초기 문서 생성을 하나의 작업 단위로 묶는다.

~~~sql
BEGIN;

INSERT INTO users (email, name)
VALUES ('tester@example.com', '테스터');

INSERT INTO documents (user_id, title, content)
VALUES (
    (SELECT id FROM users WHERE email = 'tester@example.com'),
    '기본 문서',
    '자동 생성된 문서입니다.'
);

COMMIT;
~~~

- 두 `INSERT` 구문이 모두 정상 실행된 후 `COMMIT`을 통해 DB에 영구 반영한다.

### 롤백 처리

작업 도중 오류가 발생하거나 조건이 어긋났을 때 원상태로 되돌린다.

~~~sql
BEGIN;

UPDATE documents
SET status = 'published'
WHERE id = 1;

ROLLBACK;
~~~

- `ROLLBACK`을 실행하면 `BEGIN` 이후 수행된 모든 변경사항이 완전히 무효화된다.

# 3. 비교 정리

## SQL 언어 분류 비교

| 구분 | DDL (데이터 정의어) | DML (데이터 조작어) | TCL (트랜잭션 제어어) |
|---|---|---|---|
| 목적 | 데이터 구조 정의 및 변경 | 테이블 내부 데이터 관리 | 작업 단위 제어 및 정합성 보장 |
| 대상 | 테이블, 스키마, 컬럼 | 실제 저장된 데이터 행 | 트랜잭션 상태 |
| 주요 명령 | `CREATE`, `ALTER`, `DROP` | `INSERT`, `SELECT`, `UPDATE`, `DELETE` | `BEGIN`, `COMMIT`, `ROLLBACK` |

## 식별키 비교

| 구분 | PRIMARY KEY (기본키) | FOREIGN KEY (외래키) |
|---|---|---|
| 목적 | 테이블 내 각 행을 고유하게 식별 | 다른 테이블의 기본키를 참조하여 관계 형성 |
| 제약 특성 | 고유해야 하며 NULL을 허용하지 않음 | 부모 테이블에 존재하는 값만 허용 (옵션에 따라 NULL 가능) |
| 위치 | 기준 테이블 내부 | 관계를 맺는 자식 테이블 내부 |

## 데이터 삭제 방식 비교

| 구분 | 물리 삭제 (`DELETE`) | 논리 삭제 (`UPDATE`) | 전체 초기화 (`TRUNCATE`) | 구조 삭제 (`DROP`) |
|---|---|---|---|---|
| 대상 | 조건에 맞는 데이터 행 | 데이터 상태 플래그 | 테이블의 모든 데이터 행 | 테이블 구조 및 전체 데이터 |
| 복구 난이도 | 어려움 | 쉬움 (플래그 복원) | 어려움 | 어려움 |
| 테이블 구조 유지 | 유지 | 유지 | 유지 | 완전히 제거 |

# 5. 핵심 정리

## 핵심 코드

~~~sql
BEGIN;

INSERT INTO users (email, name)
VALUES ('dev@example.com', '개발자');

UPDATE documents
SET status = 'published'
WHERE user_id = (SELECT id FROM users WHERE email = 'dev@example.com');

COMMIT;
~~~

- 트랜잭션 블록 내에서 종속 관계를 가진 데이터를 순차적으로 생성 및 갱신하고 단일 단위로 커밋한다.

## 핵심 개념

- AI 서비스의 영속성 확보를 위해 RDBMS 기반의 체계적인 저장 구조가 필수적이다.
- DDL은 구조를 관리하고, DML은 데이터를 다루며, TCL은 트랜잭션 단위 작업을 제어한다.
- `PRIMARY KEY`와 `FOREIGN KEY`는 무결성을 지키고 정규화된 1:N 관계를 구축하는 근간이다.
- `UPDATE`와 `DELETE`는 의도치 않은 전체 데이터 수정을 방지하기 위해 반드시 실행 전후 `SELECT` 검증을 거쳐야 한다.
- 트랜잭션의 `COMMIT`과 `ROLLBACK`을 통해 복합 데이터 변경 과정에서의 정합성을 보장한다.

# 6. 느낀 점

PostgreSQL과 Supabase 환경에서 데이터베이스 구조를 직접 설계하고 관리하는 전반적인 흐름을 정리했다.

단순한 CRUD 쿼리 작성에 그치지 않고, 제약조건을 통한 데이터 무결성 보장과 트랜잭션을 활용한 안전한 작업 제어의 중요성을 확인했다.

실제 서비스 구현 시 데이터 유실을 방지하기 위해 사전 SELECT 검증 습관과 논리 삭제 설계 방식을 기준에 맞게 적용해야 함을 정리했다.

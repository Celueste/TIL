## 1. 하이퍼링크와 경로

### 1.1 `<a>` 태그
`<a>` 태그는 웹 페이지에서 다른 페이지나 특정 위치로 이동할 수 있는 하이퍼링크를 만드는 태그이다.

~~~html
<a href="https://www.wikipedia.org">위키백과</a>
~~~

- `href`에는 이동할 목적지 주소나 파일 경로를 작성한다.

### 1.2 target 속성
`target`은 링크를 클릭했을 때 브라우저 창이나 탭을 어디에서 열지 결정한다.

- `_self`: 현재 창에서 연다(기본값).
- `_blank`: 새로운 탭이나 창에서 연다.
- `_parent`: 부모 프레임에서 연다.
- `_top`: 최상위 창에서 연다.

~~~html
<a href="https://www.wikipedia.org" target="_self">현재 탭에서 열기</a>
<a href="https://www.wikipedia.org" target="_blank">새 탭에서 열기</a>
~~~

### 1.3 절대 경로와 상대 경로
- **절대 경로**: 고유한 전체 주소나 최상위 루트부터 시작하는 전체 경로를 작성하는 방식이다.
  ~~~html
  <a href="https://www.google.com">구글</a>
  ~~~
- **상대 경로**: 현재 작업 파일의 위치를 기준으로 대상 파일의 위치를 지정하는 방식이다.
  - `./`: 현재 폴더
  - `../`: 한 단계 상위 폴더
  ~~~html
  <!-- 현재 파일 기준 상위 폴더의 images 디렉터리에 있는 이미지 참조 -->
  <img src="../images/photo.jpg" alt="사진">
  ~~~

## 2. 멀티미디어 태그

### 2.1 이미지 `<img>`
웹 페이지에 이미지를 표시할 때 사용하며, 닫는 태그가 없는 단독 태그이다.

~~~html
<img src="photo.jpg" alt="프로필 사진" width="300" height="200">
~~~

- `src`: 이미지 파일의 경로를 지정한다.
- `alt`: 이미지를 표시할 수 없을 때 노출되는 대체 텍스트이며, 스크린 리더 등 웹 접근성에 필수적이다.
- `width` / `height`: 이미지의 가로 및 세로 크기를 지정한다.

### 2.2 비디오 `<video>`
웹 페이지에 동영상을 삽입할 때 사용한다.

~~~html
<video src="movie.mp4" controls width="400"></video>
~~~

- `src`: 비디오 파일 경로를 지정한다.
- `controls`: 재생, 정지, 볼륨 등 컨트롤러를 화면에 표시한다.
- `autoplay`: 비디오를 자동 재생한다.
- `muted`: 음소거 상태로 재생한다. 최신 브라우저는 예기치 않은 소음 방지를 위해 `autoplay` 적용 시 `muted` 속성을 필수로 요구하는 경우가 많다.
- `loop`: 비디오 재생을 반복한다.
- `poster`: 비디오가 로딩되거나 재생되기 전에 보여줄 대표 썸네일 이미지를 지정한다.

## 3. Form과 사용자 입력

### 3.1 `<form>` 태그
사용자가 입력한 데이터를 수집하여 서버로 전송하기 위한 컨테이너 영역이다. 로그인, 회원가입, 검색 등에 사용된다.

~~~html
<form action="#" method="post">
    <!-- 입력 요소 위치 -->
</form>
~~~

- `action`: 입력 데이터를 전송하여 처리할 서버 주소이다.
- `method`: 데이터를 전송하는 HTTP 방식을 지정한다.
- `target`: 서버의 처리 결과를 표시할 창 위치를 지정한다.

### 3.2 GET과 POST
- **GET 방식**: 서버의 데이터를 조회하거나 검색할 때 주로 사용한다. 입력 데이터가 URL 뒤의 쿼리스트링 형태로 노출된다.
  ~~~html
  <form action="/search" method="get">
  ~~~
- **POST 방식**: 서버의 리소스를 생성, 수정, 삭제하는 등 상태를 변경할 때 주로 사용한다. 입력 데이터가 HTTP 요청 바디(Body)에 담겨 전달된다.
  ~~~html
  <form action="/signup" method="post">
  ~~~
  > POST 방식은 데이터가 URL에 직접 노출되지 않을 뿐 자동으로 암호화되는 것은 아니다. 실제 데이터 전송 보안을 유지하려면 HTTPS 암호화 통신을 사용해야 한다.

### 3.3 name과 value
- `name`: 서버에서 전송된 데이터를 구분하기 위한 키(Key) 이름이다.
- `value`: 서버로 전송되는 실제 값(Value)이다.
- 사용자가 직접 타이핑하지 않는 `radio`, `checkbox`와 같은 요소는 선택 시 전송될 데이터를 위해 반드시 `value` 속성을 명시해야 한다.

~~~html
<input type="radio" name="gender" value="m">
<input type="radio" name="gender" value="f">
~~~

### 3.4 id와 name의 차이
- `id`: 단일 HTML 문서 내에서 특정 요소를 유일하게 식별하기 위한 식별자이다. 문서 전체에서 중복될 수 없다.
- `name`: 폼 데이터를 서버로 전송할 때 키값으로 사용된다. 같은 그룹으로 묶이는 라디오 버튼처럼 여러 요소에 중복해서 부여할 수 있다.

~~~html
<input type="text" id="userName" name="userName">
~~~

### 3.5 `<label>` 연결
`<label>`은 폼 컨트롤의 이름표 역할을 하며, 접근성과 사용성을 향상시킨다.

- **속성 매핑 방식**: `<label>`의 `for` 값과 `<input>`의 `id` 값을 동일하게 설정한다. 텍스트를 클릭해도 해당 입력창에 자동으로 포커스가 잡힌다.
  ~~~html
  <label for="userName">이름</label>
  <input type="text" id="userName" name="userName">
  ~~~
- **태그 감싸기 방식**: `<label>` 태그 안에 `<input>`을 직접 중첩하여 작성한다.
  ~~~html
  <label>
      <input type="checkbox" name="agree" value="y"> 약관에 동의합니다.
  </label>
  ~~~

## 4. HTML5 입력 타입과 버튼

### 4.1 Radio
여러 선택지 중 단 하나만 선택할 때 사용한다. 동일한 `name` 값을 지정해야 하나의 선택 그룹으로 인식된다.

~~~html
<input type="radio" name="gender" value="m"> 남성
<input type="radio" name="gender" value="f"> 여성
~~~

### 4.2 Checkbox
여러 선택 항목을 다중 선택할 수 있도록 할 때 사용한다. 동일한 `name`을 적용하면 선택된 여러 값이 함께 전송된다.

~~~html
<input type="checkbox" name="hobby" value="sports"> 운동
<input type="checkbox" name="hobby" value="reading"> 독서
~~~

### 4.3 Select와 Option
드롭다운 형태의 선택 메뉴를 만든다. `<select>`가 목록 컨테이너를 구성하고 `<option>`이 개별 선택지를 구성한다.

~~~html
<select name="emailDomain">
    <option value="naver.com">naver.com</option>
    <option value="gmail.com" selected>gmail.com</option>
</select>
~~~

- `selected` 속성을 부여하면 기본값으로 해당 항목이 미리 선택된다.

### 4.4 Textarea
여러 줄의 긴 텍스트를 입력받을 때 사용한다.

~~~html
<textarea name="intro" rows="4" cols="40"></textarea>
~~~

- `rows`: 표시할 텍스트 줄 수를 지정한다.
- `cols`: 텍스트 영역의 가로 너비(문자 단위 폭)를 지정한다.

### 4.5 다양한 Input Type
HTML5는 입력 데이터의 성격에 맞춰 브라우저 단에서 검증 및 입력을 돕는 다양한 타입을 지원한다.

- `text`: 단일 줄 텍스트 입력
- `password`: 입력 문자를 가림 처리하는 비밀번호 입력
- `email`: 이메일 형식 자동 검증
- `number`: 숫자 전용 입력창 (`min`, `max`, `step` 지정 가능)
- `range`: 범위 슬라이더 바
- `date` / `time` / `datetime-local`: 날짜 및 시간 선택 캘린더
- `color`: 색상 선택 팔레트
- `file`: 파일 첨부 및 전송 (`accept` 속성으로 파일 확장자 제한 가능)

~~~html
<input type="number" name="userAge" min="1" max="150">
<input type="file" name="profileFile" accept="image/*">
~~~

### 4.6 Button
버튼은 목적에 따라 3가지 타입을 가진다.

~~~html
<button type="submit">가입하기</button>
<button type="reset">다시 쓰기</button>
<button type="button">일반 버튼</button>
~~~

- `type="submit"`: 폼에 작성된 모든 데이터를 서버로 전송한다.
- `type="reset"`: 사용자가 입력한 모든 양식을 초기 상태로 리셋한다.
- `type="button"`: 기본 동작이 없으며, 자바스크립트 등 별도 이벤트를 연결할 때 사용한다.

## 5. 시멘틱 태그

### 5.1 시멘틱 마크업의 정의
시멘틱(Semantic)은 '의미가 통하는'이라는 뜻이다. 시멘틱 태그는 태그명 자체만으로 해당 영역이 어떤 역할을 수행하는지 브라우저와 개발자가 직관적으로 파악할 수 있도록 만든 태그이다.

~~~html
<!-- 비시멘틱 마크업 -->
<div id="header"> ... </div>

<!-- 시멘틱 마크업 -->
<header> ... </header>
~~~

### 5.2 시멘틱 태그가 필요한 이유
- **검색엔진 최적화(SEO)**: 검색 로봇이 문서 구조를 효과적으로 분석하여 중요 콘텐츠를 정확히 인덱싱한다.
- **웹 접근성(Accessibility)**: 스크린 리더와 보조 기기가 웹 페이지의 구조와 내비게이션 영역을 정확히 식별해 사용자에게 전달한다.
- **코드 가독성 및 유지보수**: 개발자가 태그만 보고도 화면의 구획과 기능을 명확히 파악할 수 있다.

### 5.3 주요 시멘틱 태그
- `<header>`: 사이트 또는 특정 섹션의 머리말(로고, 제목 등)을 나타낸다.
- `<nav>`: 다른 페이지나 문서 내 영역으로 이동하는 내비게이션 링크 묶음이다.
- `<main>`: 문서의 유일한 핵심 본문을 감싸며, 문서당 한 번만 사용하는 것을 권장한다.
- `<section>`: 특정 주제별로 관련 콘텐츠를 그룹화하는 영역이다.
- `<article>`: 블로그 글, 뉴스 기사, 댓글처럼 독립적으로 배포하거나 재사용 가능한 단독 콘텐츠를 감싼다.
- `<aside>`: 주요 본문 흐름과 직접적이지 않은 보조 정보(사이드바, 광고 등)를 담는다.
- `<footer>`: 사이트나 특정 섹션의 하단 정보(저작권, 제작자, 약관 등)를 정의한다.

### 5.4 `<div>`와 시멘틱 태그의 사용 기준
- `<div>`: 별도의 의미적 맥락 없이 단순 스타일링(CSS 레이아웃), 스크립트 제어 래퍼로 묶을 때 사용한다.
- **시멘틱 태그**: 해당 영역이 머리말, 본문, 목록, 독립 기사 등 의미를 명확히 표현할 수 있을 때 우선적으로 채택한다.

## 6. 실습 및 코드

### 6.1 회원가입 폼 만들기
다양한 `input` 타입, `label`, `textarea`, `button`을 결합한 사용자 입력 폼이다.

~~~html
<form action="#" method="post">
    <p>
        <label for="userName">이름: </label>
        <input type="text" id="userName" name="userName" placeholder="이름을 입력하세요">
    </p>

    <p>
        <label for="userPw">비밀번호: </label>
        <input type="password" id="userPw" name="userPw" placeholder="비밀번호를 입력하세요">
    </p>

    <p>
        <span>성별: </span>
        <input type="radio" id="male" name="gender" value="m">
        <label for="male">남성</label>

        <input type="radio" id="female" name="gender" value="f">
        <label for="female">여성</label>
    </p>

    <p>
        <span>관심 취미: </span>
        <input type="checkbox" id="hobby1" name="hobby" value="sports">
        <label for="hobby1">운동</label>

        <input type="checkbox" id="hobby2" name="hobby" value="reading">
        <label for="hobby2">독서</label>

        <input type="checkbox" id="hobby3" name="hobby" value="coding">
        <label for="hobby3">코딩</label>
    </p>

    <p>
        <label for="intro">자기소개: </label><br>
        <textarea id="intro" name="intro" rows="4" cols="40"></textarea>
    </p>

    <p>
        <button type="submit">가입하기</button>
        <button type="reset">다시 쓰기</button>
    </p>
</form>
~~~

- `<label for="...">`와 `<input id="...">`를 매핑하여 클릭 범위를 레이블까지 확장한다.
- `gender` 라디오 버튼은 동일한 `name`을 지정하여 1개만 택일되도록 그룹화한다.
- `hobby` 체크박스는 동일한 `name`과 항목별 고유한 `value`를 지정해 다중 전송을 처리한다.

### 6.2 시멘틱 레이아웃 만들기
시멘틱 구조 태그를 활용해 구획화한 기본 웹 문서 레이아웃이다.

~~~html
<header>
    <h1>하루 5분 IT 뉴스</h1>

    <nav>
        <ul>
            <li><a href="#home">홈</a></li>
            <li><a href="#tech">테크 소식</a></li>
            <li><a href="#opinion">칼럼</a></li>
        </ul>
    </nav>
</header>

<main>
    <section id="tech">
        <h2>실시간 테크 뉴스</h2>

        <article>
            <h3>인공지능이 바꾸는 미래</h3>
            <p>AI 기술에 대한 뉴스 내용입니다.</p>
        </article>

        <article>
            <h3>HTML5 시멘틱 마크업</h3>
            <p>시멘틱 태그에 대한 뉴스 내용입니다.</p>
        </article>
    </section>

    <aside>
        <h4>광고 및 이벤트</h4>
        <p>코딩 입문자 할인 이벤트입니다.</p>
    </aside>
</main>

<footer>
    <p>&copy; 2026 IT News</p>
</footer>
~~~

- `<header>` 내부에 상단 제목과 `<nav>`를 배치해 문서 탐색 영역을 정의한다.
- `<main>` 내부에 뉴스 섹션(`<section>`)과 독립 기사 단위(`<article>`), 보조 사이드바(`<aside>`)를 배치해 문서의 구조적 위계를 표현한다.
- `<footer>`를 통해 문서 하단 저작권 정보를 명시한다.

## 7. 오류와 해결

### 7.1 id와 name의 혼동으로 인한 전송 누락
- **오류 원인**: 화면 요소를 지정하기 위해 `id`만 작성하고 `name` 속성을 생략하면, 폼 전송 시 서버로 데이터가 전달되지 않는다.
- **해결 방법**: `id`는 브라우저 내부 식별 및 `<label>` 연결용으로 사용하고, 서버로 전송해야 하는 모든 입력 요소에는 `name` 속성을 명시적으로 선언한다.
  ~~~html
  <!-- 올바른 작성법 -->
  <input type="text" id="userEmail" name="userEmail">
  ~~~

### 7.2 Radio의 name 불일치로 인한 다중 선택 버그
- **오류 원인**: 라디오 버튼의 `name`을 서로 다르게 지정하면 별개의 질문으로 인식되어 다중 선택이 허용된다.
- **해결 방법**: 단일 선택으로 묶여야 하는 라디오 항목들은 `name` 속성값을 완벽히 일치시킨다.
  ~~~html
  <input type="radio" name="gender" value="m">
  <input type="radio" name="gender" value="f">
  ~~~

### 7.3 선택형 입력의 value 누락
- **오류 원인**: `radio`나 `checkbox`에서 `value`를 생략하면 선택 시 서버에 의미 있는 값 대신 브라우저 기본값인 `on` 등이 전달되어 실제 선택 항목을 판별할 수 없다.
- **해결 방법**: 사용자가 직접 타이핑하지 않는 모든 선택형 입력 컨트롤에는 전송할 고유 데이터를 `value` 속성으로 지정한다.
  ~~~html
  <input type="checkbox" name="hobby" value="coding">
  ~~~

## 8. 비교 정리

| 태그 및 속성 | 구분 | 핵심 목적 | 주요 특징 |
|---|---|---|---|
| `<a>` | 링크 | 페이지/위치 이동 | `href`로 경로 지정, `target`으로 열림 창 제어 |
| `<img>` / `<video>` / `<audio>` | 미디어 | 외부 멀티미디어 삽입 | `<img>`는 단독 태그(`alt` 필수), `<video>`는 컨트롤 지원 |
| `<form>` | 데이터 전송 | 사용자 입력 컨테이너 | `action`(경로), `method`(GET/POST) 정의 |
| `id` | 식별자 | 브라우저 내 유일 식별 | 문서 내 중복 불가, `<label for>` 매핑에 사용 |
| `name` | 식별자 | 서버 전송 데이터의 키 | 동일 그룹 폼 요소 간 중복 사용 가능 |
| `value` | 데이터 | 실제 전송 값 | `radio`, `checkbox` 등 선택형 요소는 명시 필수 |
| `<radio>` | 선택 요소 | 단일 항목 택일 | 동일한 `name`으로 그룹화 필수 |
| `<checkbox>` | 선택 요소 | 다중 항목 선택 | 복수 선택 허용, 동일한 `name` 공유 가능 |
| `<select>` / `<textarea>` | 입력 요소 | 목록 선택 및 장문 입력 | `<select>`는 드롭다운, `<textarea>`는 여러 줄 텍스트 |
| 시멘틱 태그 | 레이아웃 | 영역 의미 및 역할 부여 | SEO, 웹 접근성, 가독성 향상 |
| `<div>` | 레이아웃 | 무의미한 일반 구획 분할 | CSS 스타일링 및 단순 래퍼 목적으로 사용 |

## 9. 전체 흐름 정리

~~~text
[HTML 웹 문서 상호작용 및 구조화 흐름]

1. 페이지 이동 및 리소스 구성
   - <a> 태그를 통한 문서 이동 경로 정의 (절대/상대 경로)
   - <img>, <video>, <audio>를 통한 시각/청각 미디어 출력
          |
          v
2. 사용자 데이터 입력 구조 설계 (<form>)
   - <form action="..." method="get|post"> 컨테이너 선언
   - <input>, <select>, <textarea>로 알맞은 입력 컨트롤 배치
   - <label for="..."> 연결로 접근성 확보
          |
          v
3. 전송 데이터 바인딩
   - name (서버 데이터 키) 설정
   - value (실제 전송 값) 설정
          |
          v
4. 서버 요청 전송
   - <button type="submit"> 클릭
   - 설정된 method 방식으로 지정된 action 주소로 전송
          |
          v
5. 시멘틱 구조화를 통한 완성
   <header> (헤더 및 네비게이션)
      ↓
   <main>
      ├── <section> (주제별 구역)
      │     └── <article> (독립 콘텐츠)
      └── <aside> (보조 정보)
      ↓
   <footer> (하단 정보)
~~~

## 10. 느낀 점

이번 학습을 통해 HTML이 단순한 정적 텍스트와 이미지 표시 도구를 넘어, 사용자와 상호작용하고 데이터를 수집 및 전송하는 핵심 인터페이스임을 체계적으로 정리할 수 있었다. 특히 폼을 구성할 때 `id`, `name`, `value`의 역할 차이를 명확히 구분하는 것이 데이터 누락이나 오작동을 방지하는 기본 원리임을 깨달았다. 또한 단순히 `<div>`로 화면 모양만 잡는 것이 아니라, 문서의 구조적 의미에 맞는 시멘틱 태그를 적절히 배치하는 것이 검색엔진 최적화와 웹 접근성 관점에서 왜 필수적인지 깊이 이해하게 되었다.
